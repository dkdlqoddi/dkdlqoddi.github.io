아키텍처 오버뷰

그림 설명: VWP망 내부에 Docker 컨테이너가 있고, 그 안에 Opencode가 실행되는 3중 중첩 구조.

볼륨 마운트 전략

그림 설명: 보호 대상 디렉토리는 Read-Only(RO)로 연결되고, 작업 대상 디렉토리는 Read-Write(RW)로 Docker 컨테이너에 연결됩니다.

실행 환경 제약 (마운트 누락)

그림 설명: 스크립트 실행 시 마운트되지 않은 호스트 경로를 참조하면 실행이 실패하는 과정.

호스트에는 존재하지만 컨테이너에 마운트되지 않은 파일은
스크립트에서 접근할 수 없어 에러가 발생합니다.

파이프라인 전체 구조

그림 설명: 툴 실행, 로그 분석, 결과 보고의 세 가지 단계가 연결된 파이프라인 개요입니다.

1단계: 툴 자동 실행

그림 설명: 툴 실행 노드가 밝아지고 톱니바퀴가 돌아가며 로그가 출력되는 모습입니다.

2단계: 로그 자동 분석

그림 설명: 생성된 로그가 분석 엔진으로 이동하며, 분석 엔진 내부에서 돋보기가 작동합니다.

3단계: 결과 자동 보고

그림 설명: 분석된 데이터가 보고서 모듈로 전달되어 막대그래프 형태의 결과물이 생성됩니다.

Architectural Limitations

⚠️ 1. Hallucination

환각 현상 및 낮은 기저모델 성능으로 인한 극심한 사용자 불편함

⚠️ 2. Latency Penalty

Agentic Loop 반복 횟수만큼 누적되는 방화벽 및 네트워크 응답 지연

⚠️ 3. Context Overflow

VWP망의 방대한 데이터 반환 시 LLM 컨텍스트 한계 돌파

Issue 1: Hallucination

CodeMate LLM의 치명적 오작동 사례

사내 상용 모델(CodeMate)의 추론 능력 부족으로 인해, 존재하지 않는 툴을 호출하거나 필수 인자(Parameter)를 빼먹는 JSON 오류가 매우 잦습니다.

이로 인해 사용자는 오류 메시지를 반복해서 봐야 하는 불편함을 겪게 되며, Harness의 JSON 파싱(Auto-Retry) 부담이 극도로 가중됩니다.

// 예상되는 올바른 MCP 툴 호출 { "tool": "vwp_search_logs", "args": { "query": "error" } } // 실제 CodeMate가 뱉어내는 할루시네이션 예시 { "tool": "search_db_which_doesnt_exist", "arguments": "error" // Object가 아닌 String 반환 }

VWP망의 로그 파일이나 DB 레코드 쿼리 시, 필터링되지 않은 원본 데이터(Raw Data)가 한 번에 쏟아져 들어옵니다.

이로 인해 LLM의 컨텍스트 윈도우가 즉시 가득 차게 되며, 이전 대화 내용(Memory)마저 지워지는 대형 참사가 발생합니다.

Mitigation & Next Steps

Schema Auto-Retry

Harness 계층에서 엄격하게 JSON을 파싱하고, 잘못된 호출은 LLM에게 즉각 재시도 지시

Payload Compression

API Server단에서 불필요한 로그 필드를 잘라내고 요약하여 컨텍스트 보호

Safe Whitelisting

VWP망의 데이터 손상을 막기 위해 MCP Server에서 Read-only 기능만 노출
