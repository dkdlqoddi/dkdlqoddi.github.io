DX vs AX

LLM 자동화는 무엇을 바꾸는가
— 파이프라인의 진화와 사내 LLM 연동 4가지 방법

→ 키 또는 화면 넘김으로 진행하세요.

오늘의 여정

그림 설명: 세미나 두 부의 지도. 왼쪽 강조 상자가 지금 진행하는 1부(자동화의 효과)로 세 가지 소주제를 담고, 화살표 건너 오른쪽 상자가 2부(하네스)입니다.

DX와 AX

그림 설명: 왼쪽에 디지털 전환(DX)의 특성 3가지, 오른쪽에 AI 전환(AX)의 특성 3가지가 상자로 나열되고, 가운데 화살표가 진화 방향을 표시합니다.

DX 자동화 파이프라인

그림 설명: 데이터 수집, 규칙 분기, 고정 처리, 결과 출력 네 상자가 화살표로 일렬로 이어지고, 입력 1건을 뜻하는 점이 파이프라인 위를 흘러갑니다. 클릭하면 규칙 분기 아래로 "규칙에 없는 입력은 실패"라는 약점 표시가 붉은색으로 나타납니다.

같은 파이프라인, AX로 진화

그림 설명: 앞 장과 같은 네 상자 파이프라인에서 규칙 분기가 LLM 판단으로, 고정 처리가 동적 처리로 바뀌고, 입력 점이 여전히 파이프라인 위를 흘러갑니다. 클릭하면 자연어 이해, 맥락 기억, 자기 치유 확장 상자가 아래에 나타나고, 한 번 더 클릭하면 결과에서 LLM 판단으로 되돌아가는 피드백 루프가 점선 행진 애니메이션과 함께 나타납니다.

효과 — 규칙이 못 덮는 긴 꼬리

그림 설명: 가로축은 입력의 다양성(정형에서 비정형·예외 순), 세로축은 빈도인 분포 곡선입니다. 자주 오는 정형 입력이 왼쪽 머리에 몰려 있고 규칙 기반은 이 머리 부분만 덮습니다. 규칙의 한계선 오른쪽 긴 꼬리 입력들은 실패 표시가 붙어 있습니다. 클릭하면 LLM 기반의 덮는 범위가 꼬리 끝까지 그려지며 실패 표시가 처리됨 표시로 바뀝니다.

예외마다 규칙을 하나씩 늘리는 대신, 판단 하나가 꼬리 전체를 덮습니다.

사내 LLM에 연결하는 4가지 방법

그림 설명: 추상화 수준이 낮은 것부터 높은 것 순서로 네 방법이 계단 모양으로 배치되고, 화살표 키마다 한 계단씩 나타납니다. HTTP 직접 호출, OpenAI SDK, LangChain을 지나 맨 위 오른쪽의 opencode 에이전트 위임에 도달합니다.

방법 1 — HTTP 직접 호출

①②③④ 추상화

그림 설명: Python에서 requests 라이브러리로 사내 LLM의 표준 주소에 HTTP 요청을 직접 보내는 구조입니다.

import os, requests        # 설치: pip install requests

url = os.environ["LLM_BASE_URL"] + "/chat/completions"
headers = {"Authorization":
           "Bearer " + os.environ["LLM_API_KEY"]}
body = {"model": "사내모델-v1",
        "messages": [{"role": "user",
                      "content": "REST API가 뭐야?"}]}
resp = requests.post(url, headers=headers, json=body)
print(resp.json()["choices"][0]["message"]["content"])
# 출력: "REST API는 자원 중심의 웹 통신 방식입니다."
# 참고: 표준 라이브러리 urllib만으로도 가능 (설치 0개)

표준 API 규격 그대로 · 폐쇄망 최소 설치

방법 2 — OpenAI SDK

①②③④ 추상화

그림 설명: Python에서 OpenAI SDK의 서버 주소 설정(base_url)을 사내 LLM으로 바꿔 연결하는 구조입니다.

import os
from openai import OpenAI    # 설치: pip install openai

client = OpenAI(base_url=os.environ["LLM_BASE_URL"],
                api_key=os.environ["LLM_API_KEY"])
resp = client.chat.completions.create(   # 표준 API
    model="사내모델-v1",
    messages=[{"role": "user",
               "content": "Python의 장점 하나만"}],
)
print(resp.choices[0].message.content)
# 출력: "간결하고 읽기 쉬운 문법입니다."

타입 · 스트리밍 지원 · 호환 서버의 사실상 표준

방법 3 — LangChain

①②③④ 추상화

그림 설명: Python에서 LangChain 프레임워크로 프롬프트 템플릿과 LLM을 체인으로 조립해 사내 LLM에 연결하는 구조입니다.

import os
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
# 설치: pip install langchain-openai

llm = ChatOpenAI(model="사내모델-v1",
                 base_url=os.environ["LLM_BASE_URL"],
                 api_key=os.environ["LLM_API_KEY"])
prompt = ChatPromptTemplate.from_template(
    "{topic}을 한 줄로 요약해줘")
result = (prompt | llm).invoke({"topic": "LangChain"})
print(result.content)  # "LLM 앱 조립 도구입니다."

프롬프트 · 체인 조립 · 다단계 작업에 적합

방법 4 — opencode, 에이전트에게 위임

①②③④ 추상화

그림 설명: Python이 subprocess로 opencode 에이전트를 실행하고, 에이전트가 사내 LLM과 도구를 써서 일을 통째로 처리하는 구조입니다. 에이전트 상자의 점선 테두리가 천천히 도는 애니메이션은 스스로 판단하는 자율 영역이라는 뜻입니다. 앞의 세 방법과 달리 호출이 아니라 위임입니다.

import subprocess
# 설치: curl -fsSL https://opencode.ai/install | bash
#       (또는 npm i -g opencode-ai)
# 사내 LLM: opencode.json provider에 baseURL·모델 등록

result = subprocess.run(
    ["opencode", "run", "파일 개수를 세어줘"],
    capture_output=True, text=True,   # 비대화식 1회
)
print(result.stdout)
# 출력: "현재 디렉토리에는 15개의 파일이 있습니다."

호출이 아니라 위임 · 도구 사용까지 맡김

4가지 방법 비교

표 설명: 네 방법을 추상화 수준, 설치 부담, 잘 맞는 상황 세 축으로 비교합니다. HTTP 직접은 직접 호출이며 requests 패키지가 필요하고 단발 호출에 맞습니다. OpenAI SDK는 얇은 래퍼이며 openai 패키지가 필요하고 타입과 스트리밍이 필요할 때 맞습니다. LangChain은 프레임워크이며 langchain-openai 패키지가 필요하고 다단계 체인 조립에 맞습니다. opencode는 에이전트 위임이며 별도 CLI 설치가 필요하고 도구 실행까지 통째로 맡길 때 맞습니다.

위임의 대가 — 폭이 벌어진다

그림 설명: 왼쪽의 '통째로 위임' 상자에서 오른쪽으로 결과의 폭이 부채꼴로 넓게 퍼지고 실행 결과 점들이 흩어져 있습니다. 위쪽 끝은 잘된 결과, 아래쪽 끝은 망한 결과입니다. 클릭하면 부채꼴 안에 좁은 점선 띠가 나타나며 2부의 하네스가 이 폭을 조인다는 예고가 표시됩니다.

호출은 폭이 좁고, 위임은 능력만큼 폭도 넓습니다.
넓어진 폭을 조이는 장치가 하네스 — 2부의 주제입니다.
