같은 요청, 벌어지는 결과

그림 설명: 왼쪽의 '같은 요청' 상자에서 오른쪽으로 결과의 폭이 부채꼴로 넓게 퍼진다. 부채꼴 안에 한 번의 실행 결과를 뜻하는 점 12개가 흩어져 있다. 위쪽 끝 라벨은 '잘된 결과', 아래쪽 끝 라벨은 '망한 결과'이고, 오른쪽 괄호가 전체 높이를 '결과물의 폭'으로 가리킨다.

점 하나 = 같은 요청을 한 번 실행한 결과 · 폭이 넓어 '잘된 결과'와 '망한 결과'가 함께 들어 있습니다

하네스가 폭을 조인다

그림 설명: 앞 장의 넓은 부채꼴이 좁은 띠로 조여진다. 원래의 넓은 폭은 점선 윤곽으로 남아 '하네스 없을 때의 폭'이라 적혀 있다. 하네스 4층이 띠를 조인다: 지시문과 작업 절차는 점선 쐐기로 밀고, 도구 제한은 실선 막대로 자르고, 검증 루프 문은 어긋난 결과 하나를 왼쪽으로 되돌려 보낸다. 반려 화살표는 점선 행진 애니메이션으로 살아 움직인다. 점 9개는 좁은 띠 안에 모이고, 2개는 밖에 남는다.

하네스(harness): 모델을 감싸 힘의 방향을 잡는 운영 장치 — 신입사원에게 회사의 업무 환경을 갖춰 주는 것과 같습니다

결과를 하나로 고정하는 게 아니라, 원하는 결과가 더 자주 나오게 폭을 조입니다

단, 탐색이 필요한 작업에서는 일부러 폭을 넓게 둡니다

ponytail

스킬① 지시문③ 작업 절차

그림 설명: 마름모 세 개(정말 필요한가, 이미 있는 걸로 되는가, 한 줄로 되는가)를 왼쪽부터 차례로 통과해 '최소 코드만 작성' 상자에 도달하는 의사결정 사다리. 앞의 두 마름모에서 탈락하면 아래의 '만들지 않는다'와 '있는 걸 쓴다'로 빠집니다. 실제 사다리는 7단이며 그림 아래 캡션에 전체가 적혀 있습니다.

  • 게으른 시니어: "필요 없는 코드는 쓰지 않는다"(YAGNI)를 AI에 주입하는 스킬입니다.
  • 7단 사다리: 필요한가 → 이미 있나(재사용·표준·내장·의존성) → 한 줄인가를 코드보다 먼저 따집니다.
  • 철학: 의존성과 생성 토큰을 줄이되, 이해를 건너뛴 게으름은 금지 — 다 읽고 나서 게으르게.

grill-me

스킬 · Matt Pocock① 지시문

그림 설명: 왼쪽의 모호한 요청이 가운데 질문 루프를 거쳐 오른쪽의 정제된 명세가 됩니다. 루프 위로 점선 화살표가 질문을 반복하며 요청 쪽으로 되돌아가고, 점선 행진 애니메이션으로 살아 움직입니다.

  • 집요한 인터뷰: 계획·설계를 그대로 실행하지 않고 "갈굼(grill)"으로 다듬는 커뮤니티 스킬입니다.
  • 라운드형 질문: 질문을 번호로 묶어 한 번에 던지고, 질문마다 자기 권장 답을 함께 붙입니다.
  • 철학: 파일을 남기지 않는 무상태 도구 — 산출물은 정제된 합의뿐입니다.

blindspot-flow

스킬③ 작업 절차④ 검증 루프

그림 설명: 인터뷰, 미지 영역, 명세, 보고서와 퀴즈 네 상자가 왼쪽부터 차례로 이어지는 파이프라인입니다. 마지막 상자는 머지 게이트로 강조되어 있고, 아래에 보고서에서 명세로 되돌아오는 점선 구현 루프가 행진 애니메이션과 함께 있습니다.

  • 사전 안전망: 코드를 쓰기 전에 개발자가 놓친 맹점(Blindspot)을 발굴해 문서로 남깁니다.
  • 4단계 규칙: 인터뷰 → 미지 영역 분석 → 명세화 → 병합 전 퀴즈로 이어지고, 탐색은 전담 에이전트에 위임합니다.
  • 철학: 비개발자 리뷰어도 변경을 정확히 이해하고 통제할 수 있도록 보장합니다.

fablize

플러그인 · fivetaku④ 검증 루프

그림 설명: AI가 "다 했습니다"라고 선언하면 가운데의 검증 게이트(fablize)가 가로채 증거를 요구합니다. 증거가 있으면 오른쪽 완료 확정으로 통과하고, 없으면 왼쪽 AI에게 반려됩니다. 반려 화살표는 점선 행진 애니메이션으로 살아 움직입니다.

  • 이식 실험: "Fable처럼 행동하는 Opus" — 완료 · 증거 · 검증을 절차로 강제하는 공개 플러그인입니다.
  • 4중 구성: 실행 관찰(만든 걸 실제로 실행) · 검증 게이트(근거 없는 done 거부) · 조사 프로토콜 · 태스크별 라우터.
  • 철학: 사후 게이트만이 아니라, 프롬프트 제출 시점부터 태스크에 맞는 규율을 주입합니다.

Aider

12345 자율성

그림 설명: 왼쪽의 Aider AI와 오른쪽의 터미널·Git 상자를 두 화살표가 잇습니다. 위 화살표는 파일 수정과 자동 커밋을 보내고, 아래 점선 화살표는 테스트 실패 로그를 Aider에게 되돌려 보내 루프를 이룹니다. 되돌아오는 화살표는 점선 행진 애니메이션으로 살아 움직입니다.

  • 원형(archetype): CLI에서 로컬 파일과 직접 상호작용하는 터미널 페어 프로그래밍의 원형입니다.
  • Git 연동: 수정마다 자동 커밋(기본값)하고, architect(설계)/editor(편집) 2모델 분업 모드를 제공합니다.
  • 철학: --auto-test를 켜면 테스트 실패 출력이 그대로 다음 입력이 되어 스스로 고칩니다.

Copilot Cloud Agent
