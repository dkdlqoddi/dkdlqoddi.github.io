같은 요청, 벌어지는 결과

그림 설명: 왼쪽의 '같은 요청' 상자에서 오른쪽으로 결과의 폭이 부채꼴로 넓게 퍼진다. 부채꼴 안에 한 번의 실행 결과를 뜻하는 점 12개가 흩어져 있다. 위쪽 끝 라벨은 '잘된 결과', 아래쪽 끝 라벨은 '망한 결과'이고, 오른쪽 괄호가 전체 높이를 '결과물의 폭'으로 가리킨다.

점 하나 = 같은 요청을 한 번 실행한 결과 · 폭이 넓어 '잘된 결과'와 '망한 결과'가 함께 들어 있습니다

하네스가 폭을 조인다

그림 설명: 앞 장의 넓은 부채꼴이 좁은 띠로 조여진다. 원래의 넓은 폭은 점선 윤곽으로 남아 '하네스 없을 때의 폭'이라 적혀 있다. 하네스 4층이 띠를 조인다: 지시문과 작업 절차는 점선 쐐기로 밀고, 도구 제한은 실선 막대로 자르고, 검증 루프 문은 어긋난 결과 하나를 왼쪽으로 되돌려 보낸다. 반려 화살표는 점선 행진 애니메이션으로 살아 움직인다. 점 9개는 좁은 띠 안에 모이고, 2개는 밖에 남는다.

하네스(harness): 모델을 감싸 힘의 방향을 잡는 운영 장치 — 신입사원에게 회사의 업무 환경을 갖춰 주는 것과 같습니다

결과를 하나로 고정하는 게 아니라, 원하는 결과가 더 자주 나오게 폭을 조입니다

단, 탐색이 필요한 작업에서는 일부러 폭을 넓게 둡니다

오늘의 지도 — 조여진 띠 아래에서

그림 설명: 앞 장의 조여진 띠가 화면 위쪽의 가는 리본으로 올라가고 결과 점들이 그 안에 정렬됩니다. 리본 아래에 하네스 4층 이름표가 남고, 그 아래 두 칸이 나타납니다. 왼쪽 칸은 층 하나를 조이는 스킬 다섯(ponytail, grill-me, superpowers, blindspot-flow, fablize)이고 각각 조이는 층 번호가 붙어 있습니다. 오른쪽 칸은 하네스를 통째로 담은 제품 다섯(Aider, Copilot Workspace, LangChain Data Agent, oh-my-opencode, Devin)입니다.

ponytail

스킬① 지시문③ 작업 절차

그림 설명: 마름모 세 개(정말 필요한가, 내장 기능인가, 한 줄로 되는가)를 왼쪽부터 차례로 통과해 '최소 코드만 작성' 상자에 도달하는 의사결정 사다리. 앞의 두 마름모에서 탈락하면 아래의 '만들지 않는다'와 '내장 기능 사용'으로 빠집니다.

  • 게으른 시니어: "필요 없는 코드는 쓰지 않는다"(YAGNI)를 AI에 주입하는 스킬입니다.
  • 의사결정 사다리: 정말 필요한가 → 내장 기능인가 → 한 줄로 되는가를 코드보다 먼저 따집니다.
  • 철학: 의존성과 생성 토큰을 줄여 코드베이스를 가볍고 유지보수하기 쉽게 지킵니다.

grill-me

스킬① 지시문

그림 설명: 왼쪽의 모호한 요청이 가운데 질문 루프를 거쳐 오른쪽의 정제된 명세가 됩니다. 루프 위로 점선 화살표가 질문을 반복하며 요청 쪽으로 되돌아가고, 점선 행진 애니메이션으로 살아 움직입니다.

  • 역질문 인터뷰: 모호한 지시를 그대로 실행하지 않고 AI가 먼저 질문을 던집니다.
  • 의도적 마찰: 추측에서 나오는 '자신감 있는 헛소리'를 시작 전에 차단합니다.
  • 철학: 요청 자체를 정련해 코딩 전에 완전한 합의(Shared Understanding)를 만듭니다.

superpowers

스킬③ 작업 절차

그림 설명: 구상, 계획서 작성, 계획 실행, 테스트와 리뷰 네 상자가 왼쪽부터 한 줄로 이어지는 파이프라인입니다. 코드보다 계획이 먼저라는 원칙을 나타냅니다.

  • 구조적 파이프라인: 구상 → 계획 → 실행의 엄격한 3단계를 강제하는 Claude Code 프레임워크입니다.
  • 안전장치: 무작정 코드부터 짜는 'Vibe Coding'을 막고 설계도 작성을 최우선으로 요구합니다.
  • 철학: TDD와 체계적 디버깅을 내장해 시니어 엔지니어의 규율을 AI에 주입합니다.

blindspot-flow

스킬③ 작업 절차④ 검증 루프

그림 설명: 인터뷰, 미지 영역, 명세, 보고서와 퀴즈 네 상자가 왼쪽부터 차례로 이어지는 파이프라인입니다. 마지막 상자는 머지 게이트로 강조되어 있고, 아래에 보고서에서 명세로 되돌아오는 점선 구현 루프가 행진 애니메이션과 함께 있습니다.

  • 사전 안전망: 코드를 쓰기 전에 개발자가 놓친 맹점(Blindspot)을 발굴해 문서로 남깁니다.
  • 4단계 규칙: 인터뷰 → 미지 영역 분석 → 명세화 → 병합 전 퀴즈로 이어집니다.
  • 철학: 비개발자 리뷰어도 변경을 정확히 이해하고 통제할 수 있도록 보장합니다.

fablize

스킬④ 검증 루프

그림 설명: AI가 "다 했습니다"라고 선언하면 가운데의 검증 게이트(fablize)가 가로채 증거를 요구합니다. 증거가 있으면 오른쪽 완료 확정으로 통과하고, 없으면 왼쪽 AI에게 반려됩니다. 반려 화살표는 점선 행진 애니메이션으로 살아 움직입니다.

  • 증명 요구: "완료했습니다" 선언을 가로채 증거부터 요구하는 검증 하네스입니다.
  • 완수 강제: 실제 테스트 통과 결과나 검증 로그가 있어야 게이트를 통과합니다.
  • 철학: AI의 착각이나 운에 의존하지 않는, 증거 기반의 작업 완수를 보장합니다.

제품 다섯 — 자율성 스펙트럼

그림 설명: 왼쪽 '사람이 매 단계 개입'에서 오른쪽 'AI가 통째로 자율'로 이어지는 수평 축 위에 다섯 제품이 차례로 나타납니다. Aider, Copilot Workspace, LangChain Data Agent, oh-my-opencode, Devin 순서로 오른쪽일수록 자율성이 높습니다.

오른쪽으로 갈수록 위임 범위가 넓어지고 — 1부의 결론대로 — 더 무거운 하네스가 함께 갑니다.

Aider

12345 자율성

그림 설명: 왼쪽의 Aider AI와 오른쪽의 터미널·Git 상자를 두 화살표가 잇습니다. 위 화살표는 파일 수정과 자동 커밋을 보내고, 아래 점선 화살표는 테스트 실패 로그를 Aider에게 되돌려 보내 루프를 이룹니다. 되돌아오는 화살표는 점선 행진 애니메이션으로 살아 움직입니다.

  • 터미널 기반: CLI 환경에서 로컬 파일과 직접 상호작용하는 페어 프로그래밍 AI입니다.
  • Git 연동: 수정할 때마다 자동 커밋해 작업 이력을 깔끔하게 분리하고 보존합니다.
  • 철학: 테스트 실패를 즉각 되먹여 루프를 돌며 스스로 고치는 신속함이 핵심입니다.

Copilot Workspace

12345 자율성

그림 설명: GitHub Issue, 명세, 계획, Pull Request 네 상자가 왼쪽부터 한 줄로 이어지는 파이프라인입니다. 가운데 명세와 계획 상자 위에 사람이 다듬는 지점이라는 표시와 화살표 두 개가 있습니다.

  • 플랫폼 통합: GitHub Issue에서 시작해 PR 생성으로 끝나는 클라우드 네이티브 파이프라인입니다.
  • 명세 중심: 코드 전에 명세(Spec)와 계획(Plan)을 먼저 써서 사람이 궤도를 수정하게 합니다.
  • 철학: 이슈 기반 개발(Issue-Driven Development)의 전 과정을 엔드투엔드로 보조합니다.

LangChain Data Agent

12345 자율성

그림 설명: 왼쪽의 사용자 질의가 가운데 ReAct 라우터를 거쳐 오른쪽의 세 도구(SQL 데이터베이스, 웹 검색, 사내 API)로 갈라져 연결됩니다. 도구의 관찰 결과가 라우터로 되돌아오는 점선 화살표가 행진 애니메이션과 함께 ReAct 루프를 이룹니다.

  • 확장성: 여러 외부 도구와 데이터베이스를 LLM에 연결하는 모듈형 아키텍처입니다.
  • ReAct 패턴: 생각(Reasoning) → 도구 실행(Acting) → 관찰(Observation) 주기를 반복해 정답에 접근합니다.
  • 철학: AI를 텍스트 생성기가 아니라 워크플로우 전체를 제어하는 오케스트레이터로 씁니다.

oh-my-opencode

12345 자율성

그림 설명: 위쪽의 Sisyphus 오케스트레이터 상자가 아래쪽의 세 전문 요원(Librarian 리서치, LSP 코드 지능, AST-Grep 구문 검색)에게 작업을 나눠 주고, 가운데 점선 화살표로 결과를 취합합니다.

  • 역할 분담: Sisyphus 오케스트레이터가 작업을 쪼개 서브 에이전트들에게 분배합니다.
  • 팀 구성: 리서치 · 정적 분석 · 언어 서버 모듈이 하나의 팀처럼 병렬로 구동됩니다.
  • 철학: AI가 혼자 다 하는 대신, 전문 도구들과 협력하는 '매니저'가 되게 합니다.

Devin

12345 자율성

그림 설명: 왼쪽의 AI 원과 오른쪽의 격리 샌드박스 상자가 목표와 결과 화살표로 연결됩니다. 샌드박스 안에는 브라우저, 터미널, 코드 에디터 세 도구가 들어 있고, 샌드박스의 점선 테두리가 천천히 도는 애니메이션은 자율 영역이라는 뜻입니다.

  • 완전 자율: 고수준 목표를 받아 샌드박스 안에서 수백 단계의 사고를 스스로 잇습니다.
  • 도구 사용: 브라우저로 검색하고, 에디터로 짜고, 터미널로 실행해 검증까지 수행합니다.
  • 철학: 코드 추천 도구가 아니라 임무를 완수하는 '엔지니어 동료'로 격상시킵니다.

정리 — 위임하고, 조여라

그림 설명: 요청 상자에서 넓게 퍼지는 점선 부채꼴이 1부에서 위임이 키운 폭을, 그 안의 좁은 강조 띠가 2부에서 하네스가 조인 폭을 나타냅니다. 띠 안에 결과 점들이 모여 있습니다.

① 위임 — 호출을 넘어, 일을 통째로 맡긴다

② 조임 — 지시문 · 도구 · 절차 · 검증의 4층으로 폭을 조인다

③ 증거 — 완료 선언이 아니라 검증이 일을 끝낸다

자동화를 한 층 키울 때마다, 하네스도 한 층.

끝.
