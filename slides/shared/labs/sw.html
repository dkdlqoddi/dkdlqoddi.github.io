E3 · SW 실습: 호출, 위임, 검증

Python 3.10 이상과 표준 라이브러리만 사용합니다. 기본 모드는 고정 응답의 모의 모델이며 실제 LLM, 사내 계정, 외부 API를 호출하지 않습니다. 로컬 HTTP 요청과 도구·검증·종료 흐름은 실제로 실행됩니다.

전체 실습 ZIP ↓lab.pyfixtures.jsonMCP 서버

ZIP을 풀고 터미널에서 그 폴더로 이동합니다. Windows에서 python 명령이 없다면 설치 환경의 py -3를 사용하세요. 결과는 out/작업ID/trace.json에 저장됩니다. 검증 성공 때만 answer.json이 추가됩니다.

1. 같은 입력, 두 경로

python lab.py sw --mode direct
python lab.py sw --mode agent

입력: “연결이 끊겼다가 복구됨”. 기대 출력은 label=transient_network, evidence=끊겼다가 복구입니다. direct는 입력을 한 번 보내고, agent는 도구를 요청한 뒤 관찰 결과를 다시 모델에 전달합니다.

2. 실패를 일부러 넣기

python lab.py sw --scenario invalid
python lab.py sw --scenario transient
python lab.py sw --scenario timeout
python lab.py sw --scenario no-progress
python lab.py selftest
시나리오예상 종료이유
normalcompleted / verified형식·인용·기대값 일치
invalidhandoff / unsupported_evidence원문에 없는 인용
transientcompleted / verified503 후 제한 재시도 성공
timeoutstopped / call_timeout호출이 시간 한도를 넘음
no-progressstopped / no_progress같은 미해결 결과 반복

실패 예제의 종료 코드는 2입니다. 실습의 의도된 결과입니다. 최대 3회, 호출 0.1초, 전체 2초는 빠르게 시험하기 위한 모의 환경 값이며 운영 기본값이 아닙니다. denied·missing은 도구를 사용하는 agent 모드에서 시험합니다.

3. 기록으로 차이 설명하기

  1. direct와 agent의 trace에서 tool.request 유무를 비교합니다.
  2. 성공 결과의 인용을 fixtures.json 원문과 대조합니다.
  3. 실패 작업에 answer.json이 생성되지 않았는지 확인합니다.
  4. 검사한 범위와 아직 확인하지 않은 조건을 적습니다.

선택: 실제 OpenCode 서버 연결

아래 단계는 실제 모델과 도구를 실행하고 사용량을 소비할 수 있습니다. 별도 연습 프로젝트에서 OpenCode 설치 버전·모델 연결·도구 권한을 먼저 구성하세요. 기본 실습과 자동 검증은 이 단계를 실행하지 않습니다.

  1. 공식 Server 문서에 따라 연습 프로젝트에서 서버를 시작합니다. 로컬 예: opencode serve --hostname 127.0.0.1 --port 4096.
  2. 서버에 인증을 설정했다면 클라이언트에도 OPENCODE_SERVER_PASSWORD, 필요 시 OPENCODE_SERVER_USERNAME을 환경 변수로 전달합니다. 비밀키를 자료나 명령 인자에 적지 않습니다.
  3. opencode_client.py를 실행합니다.
python opencode_client.py --prompt "연습 폴더의 fixtures.json을 읽고 SW 입력의 분류와 근거를 설명해 줘. 파일은 변경하지 마."

POST /session → POST /session/:id/message → info/parts 검사 순서입니다. 빈 응답·오류·여러 텍스트 조각을 처리합니다. timeout 때 abort를 요청하더라도 서버가 멈췄는지와 작업 폴더 변경은 직접 확인하세요. 클라이언트 timeout과 Agent 런타임의 반복 상한은 별도입니다. 실제 서버 연동은 제공된 환경에서 다시 검증해야 합니다.
