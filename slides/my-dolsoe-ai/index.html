METAPHOR

왜 하필 '돌쇠'인가

에이전트 시스템의 용어는 추상적입니다. '숙련된 설계 일꾼에게 어떻게 EDA 툴을 쥐여줄 것인가'로 바꾸면 익숙한 문제가 됩니다.

Skill · EDA MCP 도구 실행

JedAI, Siemens, SNPS MCP를 부르는 정해진 절차. 스스로 방황하지 않습니다.

Agent · 스스로 고르는 설계 일꾼

설계 단계(합성, DRC, 분석)를 보고 알맞은 MCP를 선택하는 관측-판단-실행 루프.

Orchestrator · 마름

프론트엔드·백엔드·검증 등 여러 일꾼에게 일을 나누어 맡기는 총괄 지휘역.

Harness · 마당과 연장

EDA 라이선스, PDK 룰덱, MCP 권한 담장 등 일꾼이 안전하게 일하는 판.

Flow · 설계 파이프라인

Synthesis → P&R → DRC → STA 로 이어지는 단방향 실행 순서.

Loop · 타이밍/DRC 클로저

WNS ≥ 0.0ps 및 DRC 0건이 될 때까지 파라미터를 튜닝하는 반복 구간.

Graph · 전체 아키텍처

Flow와 Loop를 노드와 조건부 엣지로 엮은 종합 설계 지도.

LAYOUT

돌쇠네 집 구조 · 파일 배치

OpenCode는 작업 디렉터리에서 git 루트까지 거슬러 올라가며 아래 경로를 자동으로 찾습니다.

my-dolsoe/
├── opencode.json
├── .opencode/
│   ├── skills/
│   │   ├── jedai-mcp/SKILL.md
│   │   ├── siemens-mcp/SKILL.md

    └── run_jedai.sh · run_calibre.sh · run_snps.sh

skills/ 는 복수형

.opencode/skills/<name>/SKILL.md — 폴더당 Skill 하나.

폴더명 = name

agents/ 는 파일명이 이름

scripts/ 는 상대경로

SKILL.md 안의 스크립트 경로는 프로젝트 루트 기준입니다.

HARNESS

Harness Engineering · 마당 짓기

모델을 바꾸지 않고 반도체 설계 결과를 바꾸는 층. 어떤 PDK를 보여주고, 어떤 EDA MCP를 쥐여주고, 어디서 막을지를 정합니다.

컨텍스트 · 무엇을 아는가

SKILL.md 본문과 references/의 파운드리 PDK 룰덱 및 SDC 제약조건.

도구 · 무엇을 쥐는가

jedai_* · siemens_* · snps_* EDA MCP 전용 도구 셋 바인딩.

권한 · 어디서 멈추는가

permission으로 gds_edit: ask, license_use: ask 승인 지점 생성.

오프라인 보장 · 밖으로 안 나간다

permission: { webfetch: "deny", bash: "ask", gds_edit: "ask" }

이 세 줄이 반도체 핵심 자산(IP)을 보호하는 돌쇠의 담장입니다.

FLOW / LOOP

Flow와 Loop · 한 줄기와 되풀이

설계 파이프라인의 1회 관통이 Flow, 타이밍과 DRC가 만족될 때까지 되돌아가는 구간이 Loop입니다.

FLOW — 합성에서 Sign-off까지

그림 설명: RTL/SDC에서 SNPS 합성, Siemens DRC, JedAI 분석으로 이어지는 단방향 Flow

LOOP — Timing Met(WNS≥0)까지 되풀이

# scripts/run_snps.sh
until grep -q "MET" data/timing_rpt.txt; do
  opencode run --agent dolsoe "버퍼링 튜닝해라"
  echo "$(grep 'Worst Slack' data/timing_rpt.txt)"
done

종료 조건 & 상한 설정

Loop는 멈추는 조건을 먼저 정하고, 최대 시도 횟수 상한(MAX)을 반드시 둡니다.

LOOP

Loop 실행 스크립트

되풀이의 한 회차마다 opencode CLI로 돌쇠를 불러 LLM이 합성 파라미터를 튜닝하게 합니다.

#!/usr/bin/env bash
# scripts/run_snps.sh
set -euo pipefail
RPT=data/timing_rpt.txt; MAX=20; n=0

# Timing Met (WNS >= 0.0)까지 LLM 돌쇠가 튜닝
until grep -q "MET" "$RPT" 2>/dev/null; do
  n=$((n+1))
  [ "$n" -gt "$MAX" ] && exit 1
  opencode run --model codemate/CodeLLMPro \
    --agent dolsoe \
    "snps-mcp 스킬로 팬아웃 제약을 조정해 슬랙을 개선해라"
  echo "[$n회차] $(grep 'Worst Slack' "$RPT")"
done
echo "완료 — Timing Closure 달성"

회차마다 LLM이 판단한다

opencode run 1회가 돌쇠를 1회 호출하며 SNPS MCP 파라미터가 튜닝됩니다.

상한이 곧 안전장치

MAX가 없으면 모델 호출이 끝없이 이어집니다. 20회 초과 시 실패 종료.

사내 EDA 연동 오프라인 실행

codemate/CodeLLMPro를 사내 환경에 두면 인터넷 없이 돕니다.

LOOP

Loop 실행 프롬프트

같은 되풀이를 사람 말로 시키는 방법 — 세션에 그대로 붙여넣으면 됩니다.

# 돌쇠에게 타이밍 클로저를 시키는 지시
@dolsoe
`data/timing_rpt.txt` 를 읽어 현재 WNS를 확인해라.
WNS < 0.0 이면 snps-mcp Skill로 버퍼링 및
클록 트리를 튜닝하고, 다시 검증하는 일을 되풀이해라.

멈출 조건: `data/timing_rpt.txt` 에 WNS >= 0.0ps
최대 시도: 20회. 넘으면 멈추고 보고해라.
매 회차마다 Worst Slack 값을 한 줄로 알려라.
인터넷은 쓰지 말고 사내 라이브러리 파일만 봐라.
끝나면 최종 슬랙과 시도 횟수를 정리해라.

조건 · 상한 · 보고 3대 원칙

되풀이 지시는 멈출 조건, 시도 상한, 보고 방식이 필수입니다.

판단은 Agent, 절차는 MCP Skill

프롬프트는 멈출 조건만 정하고, 실제 세부 절차는 MCP Skill이 수행합니다.

스크립트와 결과는 동일

자연어 지시문과 scripts/run_snps.sh는 같은 Loop의 말과 코드 버전입니다.

description: 타이밍 마진과 DRC 룰덱 위반 여부를

검사역은 스스로 설계를 고치지 않고 마름에게 되돌립니다.

GRAPH

Graph Engineering · 전체 지도로 묶기

노드는 책임 하나, 엣지는 조건. 되돌아오는 엣지가 EDA 최적화 순환(Loop)을 만듭니다.

그림 설명: 마름, 돌쇠, 개똥이, 언년이가 연결된 반도체 설계 자동화 완성형 상태 전이 그래프

LOCAL CHECKLIST

오늘 만든 것, 그대로 돌려보기

외부 의존성 없이 사내 폐쇄망 환경에서 즉시 실행하는 5단계 절차

01 로컬 모델 서버

codemate/CodeLLMPro를 내보내는 서버를 먼저 띄웁니다.

02 opencode.json

EDA MCP 프로바이더와 localhost baseURL을 등록합니다.

03 .opencode/skills/

jedai-mcp · siemens-mcp · snps-mcp 폴더 생성.

04 .opencode/agents/

dolsoe · gaeddong · maleum · eonnyeon 배치.

05 opencode 실행

"지금 타이밍 클로저 해라" 한 마디로 전체 그래프가 순환합니다.

# .opencode/board/agent-card.json
{
  "name": "dolsoe",
  "skills": ["snps-mcp", "jedai-mcp"],
  "url": "http://localhost:4001/a2a",
  "auth": "none"
}

board/inbox/에 합성/분석 작업을 붙이면 돌쇠가 가져가고,
결과는 board/outbox/에 되돌려 붙입니다.

Agent Card (발견)

누가 어떤 EDA MCP를 다룰 수 있는지 명함으로 알립니다.

Task (게시)

설계/검증 작업을 메시지로 붙이면 담당 에이전트가 집어갑니다.

Artifact (회수)

수행 결과 보고서와 로그를 같은 자리에 되돌려 놓습니다.

표준: Google A2A · Blackboard 공유 작업판 패턴

SPEC-DRIVEN

6단계 · 요구사항과 과정을 문서로

말로 시키면 세션 종료 시 사라집니다. 명세와 결정을 파일로 남겨야 다음 돌쇠가 이어받습니다.

# AGENTS.md
## 실행: `./scripts/run_snps.sh`
## 검증: `./scripts/run_calibre.sh`
## 규칙: data/gds/ 원본은 덮어쓰지 않는다

# specs/001-timing-closure.md
## 요구사항 — Target Freq 1.2GHz 달성
## 완료 조건: WNS >= 0.0ps, DRC = 0
## 검수 — 언년이가 PASS 를 준다

AGENTS.md (설계실 규칙)

RAG · LLM WIKI

7단계 · 돌쇠의 도서관 만들기

모르는 것을 지어내지 않게 하려면, 찾아 읽을 자리를 먼저 만들어 줘야 합니다.

library/ — 반도체 로컬 지식 베이스
├── sources/   # PDK 매뉴얼 · 룰덱 원문
├── index/     # 임베딩 · 벡터 색인
├── wiki/      # 엔지니어 요약 정리본
└── INDEX.md   # 전체 목차 한 장

1. PDK/SDC 수집 → 2. RAG 색인 / 위키 정리 →
3. Skill의 references로 필요 시 참조

RAG (찾아서 넣기)

PDK 룰덱 벡터 색인으로 관련 설계 가이드만 꺼냅니다.

LLM Wiki (접어서 두기)

에이전트가 툴 매뉴얼을 읽고 링크된 위키로 정리합니다.

INDEX.md (목차가 곧 지도)

어떤 PDK/IP 문서가 어디 있는지 한 장의 지도로 찾습니다.
