METAPHOR

왜 하필 '돌쇠'인가

에이전트 시스템의 용어는 추상적입니다. '숙련된 일꾼에게 어떻게 프롬프트로 연결된 MCP를 쥐여줄 것인가'로 바꾸면 익숙한 문제가 됩니다.

Skill · 프롬프트로 MCP 직접 호출

OpenCode에 연결된 JedAI, Siemens, SNPS MCP를 프롬프트로 부르는 절차.

Agent · 스스로 고르는 리서치 일꾼

질문이나 툴 유형을 보고 어떤 MCP 도구를 부를지 지시문으로 판단하는 루프.

Orchestrator · 마름

3대 MCP를 다루는 일꾼들에게 작업을 나누어 맡기고 지식을 취합하는 지휘역.

Harness · 마당과 연장

opencode.json의 MCP 서버 등록, 사내 도서관(library/), 보안 담장.

Flow · 프롬프트 파이프라인

질의 입력 → MCP 직접 호출 → 지식 추출로 이어지는 단방향 순서.

Loop · 프롬프트 튜닝 탐색

원하는 기술 사양이 완전히 확보될 때까지 프롬프트로 MCP를 되풀이 호출.

Graph · 전체 지식 아키텍처

Flow와 Loop를 노드와 조건부 엣지로 엮은 종합 지식 지도.

LAYOUT

돌쇠네 집 구조 · 파일 배치

OpenCode는 작업 디렉터리에서 git 루트까지 거슬러 올라가며 아래 경로를 자동으로 찾습니다. (스크립트 없이 MCP 직접 호출)

my-dolsoe/
├── opencode.json        # 3대 MCP 서버 등록
└── .opencode/
    ├── skills/          # fetch-*-manual
    │   ├── fetch-jedai-manual/SKILL.md
    │   ├── fetch-siemens-manual/SKILL.md
    │   └── fetch-snps-manual/SKILL.md
    └── agents/          # dolsoe · maleum ...

skills/ 는 복수형

.opencode/skills/<name>/SKILL.md — 폴더당 Skill 하나.

폴더명 = name

frontmatter의 name과 폴더 이름이 일치해야 로딩됩니다.

agents/ 는 파일명이 이름

dolsoe.md → @dolsoe 로 호출됩니다.

HARNESS

Harness Engineering · 마당 짓기

모델을 바꾸지 않고 매뉴얼 수집 결과를 바꾸는 층. opencode.json에 MCP를 연결하고, 프롬프트 권한 담장을 칩니다.

컨텍스트 · 무엇을 아는가

SKILL.md 본문과 references/의 사내 매뉴얼 색인 및 검색 키워드.

도구 · 무엇을 쥐는가

opencode.json에 등록된 jedai, Siemens_MCP, SNPS_MCP 도구 셋.

권한 · 어디서 멈추는가

permission으로 manual_export: ask, doc_edit: ask 승인 지점 생성.

오프라인 보장 · 밖으로 안 나간다

사내 폐쇄망 MCP 서버 + 로컬 LLM = 기밀 매뉴얼 외부 유출 0% 보장.

permission: { webfetch: "deny", bash: "ask", doc_edit: "ask" } — 사내 EDA 기술 자산을 보호하는 돌쇠의 담장

AGENT

2단계 · 때를 아는 Agent 만들기

이제 어떤 매뉴얼 스킬을 쓸지 사람이 고르지 않습니다. 질문의 EDA 툴 유형에 따라 에이전트가 스스로 프롬프트로 MCP를 호출합니다.

# .opencode/agents/dolsoe.md
---
description: 질문에 맞는 EDA 매뉴얼 MCP 호출 일꾼
mode: primary
model: codemate/CodeLLMPro
permission: { webfetch: "deny" }
---
엔지니어의 질문과 대상 EDA 툴을 확인한다.
- JedAI / 수율 분석 질문 → fetch-jedai-manual 호출
- Calibre / DRC 질문 → fetch-siemens-manual 호출
- 합성 / STA / SDC 질문 → fetch-snps-manual 호출
연결된 MCP 도구를 직접 호출해 data/*.md 에 저장한다.

실행 방법

opencode 실행 → Tab dolsoe → "최신 PrimeTime SDC 옵션 찾아와"

툴별 자동 분기 로직

JedAI / ML → fetch-jedai-manual (수율/마이닝)
Siemens / DRC → fetch-siemens-manual (물리검증)
Synopsys / STA → fetch-snps-manual (합성/타이밍)

매뉴얼 탐색 판단이 사람의 수작업이 아니라 에이전트 지시문으로 자동화되었습니다.

프로젝트 전역 Agent 등록

opencode.json에 정의하면 팀원 전체가 일관된 에이전트 구성을 공유합니다.

skills 명시적 바인딩

에이전트가 사용할 스킬 목록을 한정하여 의도치 않은 도구 오용을 방지합니다.

.md 지시문과의 역할 분담

.md는 행동 프롬프트, json은 모델·스킬·권한 등 시스템 설정을 담당합니다.

FLOW / LOOP

Flow와 Loop · 한 줄기와 되풀이

프롬프트로 MCP를 1회 호출하는 것이 Flow, 원하는 기술 문서가 완벽히 수집될 때까지 프롬프트를 튜닝하며 되돌아가는 구간이 Loop입니다.

FLOW — 질의에서 지식 저장까지

그림 설명: 질의 입력에서 프롬프트 MCP 호출, 내용 파싱, 지식 저장으로 이어지는 단방향 Flow

LOOP — 필수 예제가 확보될 때까지 되풀이

# CLI 환경에서 프롬프트로 MCP 반복 호출
until grep -q "Example Code" data/snps_manual.md; do
  opencode run --agent dolsoe \
    "SNPS_MCP로 PrimeTime STA 예제 찾아와라"
done

종료 조건 & 상한 설정

Loop는 멈추는 조건을 먼저 정하고, 최대 시도 횟수 상한(MAX)을 반드시 둡니다.

LOOP

Loop 실행 메커니즘

되풀이의 한 회차마다 opencode CLI 또는 세션에서 돌쇠를 불러 프롬프트로 MCP를 순환 호출합니다.

# 최신 SDC 예제 코드가 확보될 때까지 프롬프트로 Loop
DOC=data/snps_manual.md; MAX=20; n=0
until grep -q "Example Code" "$DOC" 2>/dev/null; do
  n=$((n+1)); [ "$n" -gt "$MAX" ] && exit 1
  opencode run --agent dolsoe \
    "fetch-snps-manual 스킬로 SNPS_MCP 호출해 STA 예제 찾아라"
  echo "[$n회차] $(grep 'DOC_VERSION' "$DOC" || echo '검색 중')"
done
echo "완료 — Synopsys 최신 매뉴얼 확보"

회차마다 LLM이 질의 판단

opencode run 1회가 돌쇠를 1회 호출하며 SNPS_MCP 질의가 정밀화됩니다.

상한이 곧 안전장치

MAX가 없으면 모델 호출이 끝없이 이어집니다. 20회 초과 시 실패 종료.

사내 폐쇄망 오프라인 실행

codemate/CodeLLMPro를 사내 환경에 두면 인터넷 없이 돕니다.

LOOP

Loop 실행 프롬프트

같은 되풀이를 세션 대화창에서 사람 말로 시키는 방법 — 세션에 그대로 붙여넣으면 됩니다.

# 돌쇠에게 최신 매뉴얼 수집을 시키는 지시
@dolsoe
`data/snps_manual.md` 를 읽어 현재 내용을 확인해라.
최신 SDC 예제가 없으면 fetch-snps-manual Skill로
연결된 SNPS_MCP 를 다시 호출해 예제를 가져와라.

멈출 조건: `data/snps_manual.md` 에 SDC 예제 포함
최대 시도: 20회. 넘으면 멈추고 보고해라.
매 회차마다 검색된 릴리즈 버전을 한 줄로 알려라.

조건 · 상한 · 보고 3대 원칙

되풀이 지시는 멈출 조건, 시도 상한, 보고 방식이 필수입니다.

판단은 Agent, 절차는 Skill

프롬프트는 멈출 조건만 정하고, 실제 세부 절차는 Skill이 수행합니다.

스크립트 없이 프롬프트로 완결

별도 쉘 스크립트 없이 세션 프롬프트 지시문 하나로 MCP 루프가 완결됩니다.

ORCHESTRATOR

3단계 · 누구에게 시킬지 정하는 마름

수집할 툴이 셋이면 문제가 바뀝니다. '어떤 툴 매뉴얼을 읽을까'가 아니라 '누구에게 시킬까'입니다.

- JedAI / SNPS 매뉴얼 수집 → @dolsoe 에게 위임

하인들이 가져온 매뉴얼을 사내 위키에 등록하고 누락 시 재수집.

두 리서치 일꾼 (mode: subagent)

@dolsoe 돌쇠 — Cadence & Synopsys (fetch-jedai · fetch-snps)
@gaeddong 개똥이 — Siemens Calibre (fetch-siemens-manual)

마름의 4대 책임

위임 · 수집 순서 결정 · 매뉴얼 통합 · 누락 시 재배정

그림 설명: 마름 오케스트레이터 미니 다이어그램

EVALUATOR

4단계 · 제대로 되었는지 보는 언년이

가져왔다고 끝이 아닙니다. MCP로 수집된 결과의 최신 릴리즈 날짜와 목차가 완벽한지 판정하는 독립된 눈을 둡니다.

# .opencode/agents/eonnyeon.md
---
description: MCP 수집 매뉴얼의 최신성·완결성을 검증하는 언년이
mode: subagent
model: codemate/CodeLLMPro
---
`data/*_manual.md` 결과 파일들을 대조한다.
- 최근 릴리즈 일치 & 예제 코드 완비 시 PASS
- 내용 누락이나 구버전 문서면 FAIL 및 사유 작성
판정과 근거를 `data/manual_eval_report.md` 에 남긴다.

독립된 매뉴얼 검사역 (@eonnyeon)

PASS: 최신성 & 예제 완비 → data/manual_eval_report.md 합격
FAIL: 항목 누락 → 누락 항목 적어 마름에게 재작업 요청

검사역의 4대 책임

버전 기준 해석 · 증거 데이터 확인 · 판정 · 재작업 요청

검사역은 스스로 문서를 채우지 않고 마름에게 되돌려 피드백 루프를 완성합니다.

GRAPH

Graph Engineering · 전체 지도로 묶기

노드는 책임 하나, 엣지는 조건. 프롬프트로 MCP를 직접 호출하는 완성형 상태 전이 지도입니다.

그림 설명: 마름, 돌쇠, 개똥이, 언년이가 연결된 EDA 매뉴얼 수집 및 지식화 완성형 상태 전이 그래프

AGENT SNS

5단계 · 돌쇠들의 마을 게시판

에이전트가 서로를 발견하고 일을 주고받는 층. 사람이 매번 이어주지 않아도 됩니다.

# .opencode/board/agent-card.json
{
  "name": "dolsoe",
  "skills": ["fetch-jedai-manual", "fetch-snps-manual"],
  "url": "http://localhost:4001/a2a"
}

board/inbox/에 수집 요청을 붙이면 돌쇠가 가져가고,
결과는 board/outbox/에 되돌려 붙입니다.

Agent Card (발견)

누가 어떤 EDA 툴 매뉴얼을 읽어올 수 있는지 명함으로 알립니다.

Task (게시)

매뉴얼 리서치 작업을 메시지로 붙이면 담당 에이전트가 집어갑니다.

Artifact (회수)

수집된 매뉴얼 마크다운과 로그를 같은 자리에 되돌려 놓습니다.

표준: Google A2A · Blackboard 공유 작업판 패턴

SPEC-DRIVEN

6단계 · 요구사항과 과정을 문서로

말로 시키면 세션 종료 시 사라집니다. 명세와 결정을 파일로 남겨야 다음 돌쇠가 이어받습니다.

# AGENTS.md
## 실행: `@dolsoe fetch-snps-manual 실행`
## 규칙: data/ 원본 문서는 임의로 삭제하지 않는다

# specs/001-manual-sync.md
## 요구사항 — 2026 Q3 최신 툴 릴리즈 매뉴얼 수집
## 완료 조건: 필수 예제 코드 포함 (검수: 언년이 PASS)

AGENTS.md (수집 규칙)

에이전트용 README — 프롬프트 실행, 문서 보존 경계, 관례 정의.

specs/ (무엇을 · 왜)

수집할 매뉴얼 목차 명세를 먼저 쓰고 시킵니다 (spec-kit).

docs/adr/ (결정과 근거)

버전 변경점 및 문법 적용 결정 한 건에 문서 한 장 — 아키텍처 기억.

RAG · LLM WIKI

7단계 · 돌쇠의 도서관 만들기

모르는 것을 지어내지 않게 하려면, 찾아 읽을 자리를 먼저 만들어 줘야 합니다.

library/ — 3대 EDA 툴 최신 지식 베이스
├── sources/   # JedAI · Siemens · SNPS 매뉴얼 원문
├── index/     # 임베딩 · 벡터 색인 (RAG)
├── wiki/      # 엔지니어용 요약 가이드 (LLM Wiki)
└── INDEX.md   # 전체 목차 한 장

1. MCP로 최신 매뉴얼 수집 → 2. RAG 색인 / 위키 정리 →
3. Skill의 references로 필요 시 참조

LLM Wiki (접어서 두기)

에이전트가 툴 매뉴얼을 읽고 링크된 위키로 정리합니다.

INDEX.md (목차가 곧 지도)

BEYOND THE GRAPH

더 있는 방법론들 — 조사로 덧붙임

그래프 엔지니어링 다음으로 확장되는 5가지 핵심 기법

01 MCP 표준

JedAI, Siemens, SNPS 등 EDA 툴 인터페이스를 표준화

02 Context Eng.

대용량 매뉴얼 중 질문에 필요한 페이지만 남기는 프롬프트 상위 설계

03 Evals

언년이의 판정을 자동 회귀 테스트로 굳혀 문서 품질 저하 방지

04 Human-in-Loop

사내 배포 전 엔지니어 최종 검토 강제 (permission: ask)

05 Sandboxing

안전한 격리 환경에서 MCP 도구를 실행하고 지식을 보존
