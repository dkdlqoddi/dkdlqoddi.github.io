나만의 돌쇠 AI 만들기

가장 단순한 Skill 하나에서 시작해, 시간을 판단하는 Agent를 거쳐,
여러 일꾼을 지휘하는 Orchestrator까지 — 비유로 따라가는 에이전트 설계

Skill → Agent → Orchestrator

→ 키 또는 화면 넘김으로 진행하세요.

METAPHOR

왜 하필 '돌쇠'인가

에이전트 시스템의 용어는 추상적입니다. 그런데 '일 잘하는 일꾼에게 어떻게 시킬 것인가'로 바꾸면 전부 익숙한 문제가 됩니다.

Skill · 한 가지 일

돌쇠에게 시키는 정해진 절차 + 도구. 스스로 판단하지 않습니다.

Agent · 스스로 고르는 돌쇠

상황과 시각을 보고 알맞은 Skill을 선택하는 관측-판단-실행 루프.

Orchestrator · 마름

하인이 둘 이상일 때 누구에게, 어떤 순서로 시킬지 결정하는 지휘역.

Harness · 마당과 연장

돌쇠가 일하는 판. 컨텍스트, 도구, 권한, 오프라인 가드레일.

Flow · 작업도

시작부터 끝까지 이어지는 한 줄기의 단방향 실행 순서.

Loop · 되풀이

조건이 충족될 때까지(예: 항아리 10/10) 되돌아가는 반복 구간.

Graph · 전체 지도

Flow와 Loop를 노드와 조건부 엣지로 엮은 종합 아키텍처.

LAYOUT

돌쇠네 집 구조 · 파일 배치

OpenCode는 작업 디렉터리에서 git 루트까지 거슬러 올라가며 아래 경로를 자동으로 찾습니다.

my-dolsoe/
├── opencode.json
├── .opencode/
│   ├── skills/
│   │   ├── draw-water/SKILL.md
│   │   ├── chop-wood/SKILL.md
│   │   └── cook-meal/SKILL.md
│   └── agents/
│       ├── dolsoe.md · gaeddong.md
│       └── maleum.md · eonnyeon.md
└── scripts/
    └── draw.sh · chop.sh · cook.sh

skills/ 는 복수형

.opencode/skills/<name>/SKILL.md
폴더 하나당 Skill 하나가 배치됩니다.

폴더명 = name

frontmatter의 name과 폴더 이름이 정확히 같아야 올바르게 로딩됩니다.

agents/ 는 파일명이 이름

dolsoe.md → @dolsoe, gaeddong.md → @gaeddong 으로 호출됩니다.

scripts/ 는 상대경로

SKILL.md 안의 스크립트 경로는 프로젝트 루트 기준 상대경로입니다.

SKILL · @dolsoe

1단계 · 가장 간단한 Skill 만들기

"돌쇠야, 물 길어와." — 판단 없이 정해진 절차만 밟는 실행 단위를 파일 하나로 만듭니다.

# .opencode/skills/draw-water/SKILL.md
---
name: draw-water
description: 항아리가 비었을 때 우물에서 물을
  길어 항아리를 채운다. 물·세면 준비가
  필요할 때 사용한다.
---
## 절차
1. `data/jar.txt` 의 현재 물 양을 읽는다.
2. 가득 차 있으면 아무 것도 하지 않고 끝낸다.
3. `scripts/draw.sh` 를 실행해 한 두레박 붓는다.
4. 가득 찰 때까지 3번을 반복한다.
## 완료 조건 — `data/jar.txt` 가 10/10

인식되는 frontmatter는 5개뿐

name·description은 필수, license·compatibility·metadata는 선택입니다.

name 규칙이 엄격하다

소문자와 하이픈만 허용되며(1~64자), 폴더명과 완벽히 일치해야 합니다.

새벽 05~08시에 마름이 돌쇠에게 맡기면 이 Skill을 사용합니다.

그림 설명: draw-water 스킬이 강조된 미니 다이어그램

"돌쇠야, 장작 좀 패라." — 같은 틀에 절차만 바꾸면 두 번째 Skill이 됩니다.

# .opencode/skills/chop-wood/SKILL.md
---
name: chop-wood
description: 장작더미가 모자랄 때 뒷산 나무를
  패서 장작을 채운다. 낮 시간 땔감 준비가
  필요할 때 사용한다.

1. `data/woodpile.txt` 의 장작 개수를 읽는다.

3. `scripts/chop.sh` 를 실행해 한 아름 팬다.
4. 20개가 될 때까지 3번을 반복한다.

.opencode/skills/chop-wood/SKILL.md 경로와 name 값이 어긋나면 인식되지 않습니다.

경로는 프로젝트 기준 상대경로

scripts/chop.sh 처럼 적어야 어느 컴퓨터나 환경에서도 그대로 돕니다.

"개똥아, 저녁 지어라." — 앞선 두 Skill의 결과를 이어받는 세 번째 실행 단위입니다.

HARNESS

Harness Engineering · 마당 짓기

모델을 바꾸지 않고 결과를 바꾸는 층. OpenCode에서는 무엇을 보여주고, 어떤 도구를 쥐여주고, 어디서 막을지를 설정으로 정합니다.

컨텍스트 · 무엇을 아는가

SKILL.md 본문과 references/. 필요할 때만 읽히도록 잘게 나눕니다.

도구 · 무엇을 쥐는가

read · edit · bash. 로컬 스크립트만 부르게 하고 web 계열은 뺍니다.

권한 · 어디서 멈추는가

permission으로 edit: ask, bash: ask 처럼 사람 승인 지점을 만듭니다.

오프라인 보장 · 밖으로 안 나간다

webfetch·websearch 차단 + localhost 모델 = 완전한 로컬 폐쇄 루프.

permission: { webfetch: "deny", bash: "ask", edit: "ask" }

이 세 줄이 돌쇠의 담장입니다.

AGENT

2단계 · 때를 아는 Agent 만들기

이제 어떤 Skill을 쓸지 사람이 고르지 않습니다. 로컬 시계를 읽고 에이전트가 스스로 고릅니다.

# .opencode/agents/dolsoe.md
---
description: 시각에 따라 알맞은 집안일 Skill을
  골라 실행하는 돌쇠
mode: primary
model: codemate/CodeLLMPro
temperature: 0.1
permission:
  webfetch: deny
---
먼저 `date +%H` 로 현재 시각을 확인한다.
05~08 → draw-water
09~16 → chop-wood
17~21 → cook-meal
스킬을 불러 실행한다.

실행 방법

opencode 실행 → Tab으로 dolsoe 선택 → "지금 할 일 해라"

시각별 분기 로직

05–08 → draw-water (새벽 물)
09–16 → chop-wood (낮 장작)
17–21 → cook-meal (저녁 밥)
그 외 → 대기

판단이 코드가 아니라 에이전트 지시문으로 옮겨졌습니다.

FLOW / LOOP

Flow와 Loop · 한 줄기와 되풀이

한 번의 실행이 지나가는 한 줄기가 Flow, 조건이 찰 때까지 되돌아가는 구간이 Loop입니다.

FLOW — 시각 확인에서 완료까지

그림 설명: 시각 확인에서 Skill 선택, 스크립트 실행, 결과 확인으로 이어지는 단방향 Flow

LOOP — 항아리가 찰 때까지 되풀이

# scripts/draw.sh
until [ "$(cat data/jar.txt)" = "10/10" ]; do
  opencode run --agent dolsoe "한 두레박 채워라"
  echo "$(cat data/jar.txt) 채움"
done

종료 조건 & 상한 설정

Loop는 멈추는 조건을 먼저 정하고, 무한 반복을 막기 위한 최대 시도 횟수를 반드시 둡니다.

LOOP

Loop 실행 스크립트

되풀이의 한 회차마다 opencode CLI로 돌쇠를 불러 LLM이 판단하게 합니다.

#!/usr/bin/env bash
# scripts/draw.sh
set -euo pipefail
JAR=data/jar.txt; MAX=20; n=0

# 한 두레박은 LLM(돌쇠)이 판단해 처리한다
until [ "$(cat "$JAR")" = "10/10" ]; do
  n=$((n+1))
  [ "$n" -gt "$MAX" ] && exit 1
  opencode run --model codemate/CodeLLMPro \
    --agent dolsoe \
    "draw-water Skill로 한 두레박만 채워라"
  echo "[$n] $(cat "$JAR")"
done
echo "완료 — 항아리 가득"

회차마다 LLM이 판단한다

opencode run 한 번이 돌쇠를 한 번 부르는 것 — 그 안에서 Skill이 실행됩니다.

상한이 곧 안전장치

MAX가 없으면 모델 호출이 끝없이 이어질 수 있습니다. 20회 초과 시 실패로 종료합니다.

로컬 모델로 오프라인 실행

codemate/CodeLLMPro를 localhost 엔드포인트에 두면 인터넷 없이 돕니다.

LOOP

Loop 실행 프롬프트

같은 되풀이를 사람 말로 시키는 방법 — 세션에 그대로 붙여넣으면 됩니다.

# 돌쇠에게 되풀이를 시키는 지시
@dolsoe
`data/jar.txt` 를 읽어 현재 물 양을 확인해라.
10/10 이 아니면 draw-water Skill을 실행하고,
다시 읽어 확인하는 일을 되풀이해라.

멈출 조건: `data/jar.txt` 가 10/10
최대 시도: 20회. 넘으면 멈추고 보고해라.
매 회차마다 현재 값을 한 줄로 알려라.
인터넷은 쓰지 말고 프로젝트 안 파일만 봐라.
끝나면 마지막 값과 시도 횟수를 정리해라.

조건 · 상한 · 보고 3대 원칙

되풀이 지시는 멈출 조건, 시도 상한, 보고 방식이 있어야 안전합니다.

판단은 Agent, 절차는 Skill

프롬프트는 언제 멈출지만 정하고, 실제 세부 절차는 Skill이 수행합니다.

스크립트와 결과는 동일

자연어 지시문과 scripts/draw.sh는 같은 Loop를 말과 코드로 적은 것입니다.

ORCHESTRATOR

3단계 · 누구에게 시킬지 정하는 마름

하인이 둘이면 문제가 바뀝니다. '무엇을 할까'가 아니라 '누구에게 시킬까'입니다.

# .opencode/agents/maleum.md
---
description: 시각을 보고 돌쇠와 개똥이에게
  일을 나눠 맡기는 마름
mode: primary
model: codemate/CodeLLMPro
---
`date +%H` 로 시각을 먼저 확인한다.
05~16 이면 @dolsoe 에게 맡긴다.
17~21 이면 @gaeddong 에게 맡긴다.
두 하인의 보고를 한 줄로 합쳐 알린다.
실패한 일은 다른 하인에게 다시 맡긴다.

mode: subagent 로 만든 두 하인

@dolsoe 돌쇠 — 물과 땔감 (draw-water · chop-wood)
@gaeddong 개똥이 — 부엌일 (cook-meal)

마름의 4대 책임

위임 · 순서 결정 · 결과 병합 · 실패 시 재배정

그림 설명: 마름 오케스트레이터 미니 다이어그램

EVALUATOR

4단계 · 제대로 되었는지 보는 언년이

시켰다고 끝이 아닙니다. 프롬프트대로 되었는지 판정하는 눈을 따로 둡니다.

# .opencode/agents/eonnyeon.md
---
description: 시킨 프롬프트대로 일이 되었는지
  대조해 판정하는 언년이
mode: subagent
model: codemate/CodeLLMPro
---
원래 지시문과 `data/` 결과 파일을 대조한다.
조건을 모두 채웠으면 PASS, 아니면 FAIL.
FAIL이면 빠진 항목을 목록으로 적는다.
판정과 근거를 `data/report.md` 에 남긴다.
스스로 고치지 않고 마름에게 되돌린다.

독립된 검사역 (@eonnyeon)

PASS: 조건 완비 → data/report.md 합격 기록
FAIL: 조건 미달 → 빠진 항목 적어 마름에게 재작업 요청

검사역의 4대 책임

기준 해석 · 증거 확인 · 판정 · 재작업 요청

검사역은 스스로 수정하지 않고 마름에게 되돌려 피드백 루프를 완성합니다.

GRAPH

Graph Engineering · 전체 지도로 묶기

노드는 책임 하나, 엣지는 조건. 되돌아오는 엣지가 순환(Loop)을 만듭니다.

그림 설명: 마름, 돌쇠, 개똥이, 언년이가 유기적으로 연결된 완성형 상태 전이 그래프

LOCAL CHECKLIST

오늘 만든 것, 그대로 돌려보기

외부 의존성 없이 로컬 환경에서 즉시 실행하는 5단계 절차

01 로컬 모델 서버

codemate/CodeLLMPro를 내보내는 서버를 먼저 띄웁니다.

02 opencode.json

codemate 프로바이더와 localhost baseURL을 등록합니다.

03 .opencode/skills/

draw-water · chop-wood · cook-meal 세 폴더 생성.

04 .opencode/agents/

dolsoe · gaeddong · maleum · eonnyeon 배치.

05 opencode 실행

"지금 할 일 해라" 한 마디로 전체 그래프가 순환합니다.

바깥으로 나가는 호출은 한 건도 없습니다. 모델도, 도구도, 상태도 전부 이 컴퓨터 안에 있습니다.

BEYOND

그래프 다음 · AI Tool 방법론 지도

Skill · Agent · Flow · Loop · Graph 위에 얹는 층들입니다. 하나씩 더해도 앞의 구조는 그대로 씁니다.

Agent SNS (A2A)

에이전트끼리 서로를 발견하고 일을 주고받는 표준 마을 게시판 통신

Spec-Driven Dev

명세를 먼저 쓰고, 그 기준으로 결과를 검수 (GitHub spec-kit)

ADR 기록

결정 한 건에 문서 한 장 — 세션이 바뀌어도 남는 아키텍처 기억

RAG · LLM Wiki

돌쇠가 찾아 읽을 도서관 — 원문을 색인하거나 위키로 정리

Context Engineering

지금 이 순간 모델이 볼 것만 남기는 정교한 입력 설계

Evals

언년이의 판정을 자동 시험으로 굳혀 기능 후퇴를 방지

Sandboxing

컨테이너·microVM 안에서만 격리된 채로 도구를 실행

AGENT SNS

5단계 · 돌쇠들의 마을 게시판

에이전트가 서로를 발견하고 일을 주고받는 층. 사람이 매번 이어주지 않아도 됩니다.

# .opencode/board/agent-card.json
{
  "name": "dolsoe",
  "skills": ["draw-water", "chop-wood"],
  "url": "http://localhost:4001/a2a",

모르는 것을 지어내지 않게 하려면, 찾아 읽을 자리를 먼저 만들어 줘야 합니다.

library/ — 로컬 지식 베이스
├── sources/   # 원문 그대로 보관
├── index/     # 임베딩 · 벡터 색인
├── wiki/      # 사람이 읽는 요약본
└── INDEX.md   # 전체 목차 한 장

1. 원문을 sources/에 수집

3. Skill의 references로 필요 시 참조
