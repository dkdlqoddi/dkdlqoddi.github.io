## 2026-07-23 — 기존 예시 데크의 인라인 스타일을 그대로 쓰지 않고 확장한다

- 결정: 예시 발표자료의 인라인 스타일 세 개(`.kbd`, `pre` 테두리, `.small`)를 그대로 가져오되, 여기에 제목 대문자화 차단과 구조 그림용 스타일을 추가한다.
- 이유: 설계 문서 결정 20이 제목 대문자화를 막으라고 정했다. 발표 엔진 테마가 제목을 모두 대문자로 바꾸기 때문이다. 또 5장 구조 그림을 그리려면 상자와 화살표를 배치할 스타일이 필요하다.
- 검토한 대안: 그림을 SVG 파일로 따로 만드는 방법. 기각 — 외부 파일이 하나 늘고, 발표 엔진 확장 기능 없이도 HTML과 CSS만으로 충분히 그릴 수 있다.
- 보수적 선택 여부: 예. 새 CSS는 이 데크 안에만 넣고 공용 스타일 파일은 건드리지 않는다.
- 계획과의 이탈: 없음.
- 사용자 확인 필요: 아니오.

## 2026-07-23 — 구조 그림에서 두 입구의 선을 각각 분리

- 결정: 5장 구조 그림에서 두 입구가 하나의 선을 공유하던 것을, 입구마다 별도의 선이 나가도록 고쳤다.
- 이유: 브라우저로 확인해 보니 두 선이 거의 같은 위치에 겹쳐 하나처럼 보였다. 설계 문서 결정 6은 "화살표는 둘이다"라고 정했다. 두 입구가 형제 관계라는 것이 이 그림의 핵심 메시지다. 선이 하나로 보이면 그 메시지가 전달되지 않는다.
- 검토한 대안: 두 선의 간격만 벌리는 방법. 기각 — 상자 높이가 달라지면 다시 겹친다. 각 선을 자기 상자의 세로 중앙에 붙이는 편이 확실하다.
- 보수적 선택 여부: 아니오.
- 계획과의 이탈: 없음. 설계 문서 결정 6을 지키기 위한 수정이다.
- 사용자 확인 필요: 아니오.

## 2026-07-23 — 브라우저 실검증 완료, 항목 간격만 조정

- 결정: 20장 전부를 브라우저에서 확인했다. 항목 사이 여백만 조금 좁혔다. 그 외 내용은 설계 문서대로 두었다.
- 이유: 도구 다섯 묶음을 보여주는 장에서 소제목과 설명 사이가 너무 벌어져 있었다. 여백을 좁히니 한 화면에 편하게 들어왔다.
- 검토한 대안: 글자 크기를 줄이는 방법. 기각 — 발표장 뒷자리에서 안 보인다. 여백을 줄이는 편이 낫다.
- 보수적 선택 여부: 예. 글자 크기는 그대로 두었다.
- 계획과의 이탈: 없음.
- 사용자 확인 필요: 아니오.

### 검증 결과 기록

- 목록 파일 형식 검사 통과.
- 목록의 폴더 이름과 실제 폴더가 일치.
- 예시 발표자료 폴더는 그대로 남아 있음.
- 발표자료가 바깥 인터넷에서 가져오는 파일 0건.
- 발표 엔진 파일 네 개 모두 제자리에 있음.
- 화면 확대를 막는 설정 없음.
- 배포에 필요한 표시 파일 그대로 있음.
- 슬라이드 20장.
- 브라우저 오류와 경고 0건. 넓은 화면과 좁은 화면 모두 확인.
- 랜딩 목록에 새 항목 하나만 보이고 예시는 사라짐.

## 2026-07-23 — 공개 문서에서도 접근 경계 세부를 뺀다

- 결정: 미지 항목 정리 문서와 요구사항 문서에 남아 있던 접근 경계 세부를 성격 수준으로 낮췄다. 뺀 내용은 비공개 파일로 옮겼다. 저장소 규모 정보와 인증 조달 경로도 함께 뺐다.
- 이유: 변경 분석에서 지적받았다. 슬라이드에서 그 세부를 뺀 이유는 "발표자료가 공개 웹사이트에 남기 때문"이었다. 그런데 산출물 문서가 들어가는 폴더도 같은 사이트에서 주소로 열린다. 슬라이드만 가리고 문서를 열어 두면 방어가 절반만 적용된 셈이다.
- 검토한 대안: 산출물 문서를 저장소 밖으로 옮기는 방법. 기각 — 이 프로젝트의 규칙이 산출물을 그 폴더에 두라고 정하고 있다. 규칙을 바꾸는 것은 이번 작업 범위가 아니다.
- 보수적 선택 여부: 예. 판단이 애매한 항목은 전부 빼는 쪽을 골랐다.
- 계획과의 이탈: 없음. 설계 문서 결정 8을 문서에도 일관되게 적용한 것이다.
- 사용자 확인 필요: 아니오. 이미 "같은 기준 적용"으로 답을 받은 사항이다.

## 2026-07-23 — 구조 그림에 대체 설명을 넣고 줄바꿈을 막는다

- 결정: 구조 그림 두 개에 화면 낭독기용 설명을 붙였다. 그리고 그림이 좁은 화면에서 줄바꿈되지 않도록 막았다.
- 이유: 그림이 상자와 선으로만 그려져 있어 눈으로 보지 않으면 내용을 알 수 없었다. 또 줄바꿈이 일어나면 "입구 둘이 중개 서버로"라는 배치가 무너진다. 그러면 설계 문서가 틀렸다고 못 박은 3단 직렬 모양으로 보인다.
- 검토한 대안: 그림 아래 본문에 같은 설명을 눈에 보이게 적는 방법. 기각 — 이미 있는 설명 문장과 겹쳐 슬라이드가 장황해진다.
- 보수적 선택 여부: 예. 줄바꿈은 실제로 일어나지 않을 가능성이 크지만 막아 두었다.
- 계획과의 이탈: 없음.
- 사용자 확인 필요: 아니오.
