# DX vs AX 발표자료 종합 개선 설계 문서

- 날짜: 2026-08-19
- 입력: [2026-08-19-dx-ax-redesign-requirements.md](2026-08-19-dx-ax-redesign-requirements.md), [2026-08-19-dx-ax-redesign-unknowns.md](2026-08-19-dx-ax-redesign-unknowns.md)

## 목적과 배경

이 저장소는 발표 슬라이드를 웹페이지로 공개하는 개인 사이트입니다.
그중 "DX vs AX" 발표자료를 크게 손봅니다.
용어 확정: 이 발표에서 DX는 디지털 전환(Digital Transformation), AX는 AI 전환(AI Transformation)을 뜻합니다.
선행 요구사항 문서의 다른 풀이(개발자 경험/에이전트 경험)는 이 정의로 대체합니다.
이 자료는 파이썬 자동화가 규칙 기반(DX)에서 AI 판단 기반(AX)으로 바뀌는 흐름을 설명합니다.
발표의 적용 환경은 사내 폐쇄망입니다. 회사 내부에 설치된 LLM 서버에 연결하는 상황을 전제합니다.

지금 자료에는 네 종류의 문제가 있습니다.
첫째, 코드 예시에 사실과 다른 내용이 있습니다. 존재하지 않는 설치 명령과 옛날 실행 옵션이 실려 있습니다.
둘째, 슬라이드마다 색을 직접 적어 넣어(110곳) 인쇄하면 강조색이 흰 종이에서 거의 보이지 않습니다.
셋째, 설명 순서가 비슷한 비교 그림 네 장으로 시작해 늘어집니다.
넷째, 다섯 개 발표자료가 같은 디자인 코드를 각자 복사해 들고 있어, 한 곳의 수리가 다른 곳에 전달되지 않습니다.
실제로 원본 격인 sample 템플릿과 2개 자료의 복사본이 이미 깨져 있고, integrated-architecture 자료는 뒷부분 14장이 아예 표시되지 않습니다.

이번 작업은 네 문제를 한 번에 해결합니다.
공통 디자인을 공유 CSS 파일 하나로 모으고, 다섯 자료 전부가 그 파일을 쓰게 바꿉니다.
DX vs AX 자료는 새 설명 구조로 다시 만들고, 코드 예시를 공식 문서 기준으로 정정합니다.

| 11 | 비교표의 "의존성 없음" 표기를 "requests 패키지"로 정정한다 | requests는 별도 설치가 필요한 외부 패키지임(공식 문서 확인) |

| 15 | 인쇄 방어를 deck-base.css에 모은다: 장식 숨김, 색 복구, 화면 넘침 규칙 해제 | 현재는 PDF 저장 시 내용이 잘리고 장식이 종이에 찍히는 결함이 있음 |

| 19 | 발표 목록 파일(slides.json)의 이 자료 설명 문구를 새 구성에 맞게 다듬는다 | 목록 카드의 설명이 새 서사와 어긋나지 않게 함. 등록 날짜는 이력이므로 유지 |

## 동작 방식

### 1. 공유 CSS 파일 (slides/shared/deck-base.css)

다섯 자료가 각자 들고 있던 공통 스타일을 한 파일로 모읍니다.
파일 내용은 위에서 아래로 다음 블록 순서입니다.

1. **색·글꼴 변수**: 배경(#0e0e0e), 본문(#dedede), 밝음(#fcfcfb), 흐림(#9aa0a6), 경계선(#2a2b2a), 강조(--accent: #00dddd), 오류(--danger: #f05050). 테마 파일에 같은 우선순위의 변수 선언이 있어, 파일 순서와 무관하게 이기도록 한 단계 강한 표기(html:root)로 선언합니다.
2. **기본 타이포그래피**: 글꼴 목록은 Montserrat 다음 Pretendard 순서입니다. 영어는 Montserrat, 한글은 Pretendard로 표시됩니다. 제목의 대문자 강제 변환을 끕니다. 한글 줄바꿈 규칙(단어 단위)을 켭니다.
3. **페이지 전환 선언**: 목록 페이지와 자료 사이를 부드럽게 오가는 효과입니다. 동작 축소 설정에서는 꺼집니다.
4. **도형 공통 클래스**: 그림(.diag), 흐림(.dim), 밝음(.bright), 강조(.accent), 오류(.danger), 숨긴 설명문(.visually-hidden) 등.
5. **모서리 장식(HUD)과 은하 배경 캔버스의 위치 규칙**: 해당 HTML 요소가 없는 자료에서는 아무 일도 일어나지 않습니다.
6. **표지 강조 효과**: 첫 장의 제목이 1단계(h1)든 2단계(h2)든 모두 빛나게 합니다.
7. **화면 넘침 방지(EVA VIEW)**: 슬라이드 내용이 화면 높이를 넘으면 안쪽 스크롤로 대피시키는 안전장치입니다.
8. **동작 축소 방어**: 움직임을 줄여달라는 이용자 설정을 존중합니다. 모든 전환을 즉시 끝내고, 은하 배경은 흐린 정지 화면만 남깁니다. 짝 전환 차단 규칙은 현행 dx 자료 105행의 검증된 문구를 글자 그대로 복사하고, 짧게 고치면 무력화된다는 경고 주석을 답니다.
9. **인쇄 방어**: 종이에 찍을 때 배경 장식(모서리 장식, 은하)을 숨깁니다. 상속 색을 쓴 도형은 검정으로 되돌립니다. 화면 넘침 방지 규칙을 해제해 긴 슬라이드도 끝까지 인쇄되게 합니다. 해제는 인쇄 메뉴와 PDF 내보내기 두 경로 모두에 적용합니다.

각 자료의 머리(head)에서 링크 순서는 고정입니다: 기본 리셋, reveal 본체, black 테마, 글꼴 2종, deck-base.css?v=1, 코드 복사 버튼 CSS, 마지막에 자료 고유 스타일.
자료 고유 스타일이 항상 마지막이므로, 각 자료는 공통값을 자유롭게 덮어쓸 수 있습니다.
흰 화면 번쩍임 방지 2종은 저장소 규칙대로 각 자료 안에 남깁니다. 색상 방식 선언(meta color-scheme)과 html 배경색 지정 한 줄입니다.

### 2. 새 DX vs AX 자료의 흐름 (11장)

1. **표지**: 상단 소제목 라벨(eyebrow, 발표자·주제 표기), 제목 "DX vs AX", 진행 안내 문구("→ 키 또는 화면 넘김으로 진행하세요").
2. **용어 정립**: 왼쪽에 DX(규칙 기반, 고정 로직, 정형 데이터), 오른쪽에 AX(LLM 추론, 동적 판단, 비정형 데이터)를 3개씩 배치합니다. 오른쪽 열은 클릭 시 등장합니다.
3. **DX 파이프라인**: 데이터 수집, 규칙 분기, 고정 처리, 결과 출력 네 상자가 일렬로 이어집니다. 클릭하면 "예외 입력이 오면 실패"라는 약점 표시가 오류색으로 나타납니다.
4. **AX로 진화 (짝 전환)**: 3장과 같은 좌표계의 그림입니다. 넘어가는 순간 "규칙 분기" 상자가 "LLM 판단"으로, "고정 처리"가 "동적 처리"로 부드럽게 바뀝니다. 이어서 클릭마다 확장 요소(비정형 입력, 맥락 기억, 자기 치유, 피드백 고리)가 아래에 등장합니다.
5. **로드맵**: 사내 LLM에 연결하는 4가지 방법을 추상화 사다리 그림으로 예고합니다. 왼쪽 아래(직접 호출)에서 오른쪽 위(에이전트 위임)로 올라갑니다.
6. **방법 1 — HTTP 직접 호출**: 구조 그림 한 줄, requests 코드(최대 12줄), 하단 특징 문구 "표준 API 규격 그대로 · 폐쇄망 최소 설치". 설치 표기를 정정하고 표준 라이브러리(urllib) 대안을 비고로 답니다.
7. **방법 2 — OpenAI SDK**: 구조 그림, 코드(최대 12줄), 하단 특징 문구 "타입·스트리밍 지원 · 호환 서버의 사실상 표준". 호환 서버 표준 API를 쓰는 이유를 주석 한 줄로 답니다.
8. **방법 3 — LangChain**: 구조 그림, 코드(최대 12줄, 설치 패키지명 langchain-openai로 정정), 하단 특징 문구 "프롬프트·체인 조립 · 다단계 작업에 적합".
9. **방법 4 — opencode 위임**: 구조 그림에서 opencode 상자를 "에이전트"로 구별해 그립니다. 코드(최대 12줄): 공식 설치 주석, `opencode run` 호출, 출력 예시. 하단 특징 문구 "호출이 아니라 위임 · 도구 사용까지 맡김".
10. **비교표**: 네 방법을 추상화 수준(직접 호출/얇은 래퍼/프레임워크/에이전트 위임), 설치(폐쇄망 관점), 잘 맞는 상황 세 축으로 비교합니다. 행이 하나씩 등장합니다.
11. **끝**: 목록으로 돌아가는 링크.

모든 그림은 상속 색 체계로 칠하고, 낭독기용 설명문과 그림 역할 표시(role="img")를 유지합니다.
내용 높이 상한: 단계 공개가 있는 장은 660px, 없는 장은 700px입니다.
3장과 4장은 짝 전환과 단계 공개를 함께 쓰므로 엄격한 쪽인 660px를 따릅니다.

### 3. 다섯 자료 마이그레이션

세 자료(sample, design-ax-transition, integrated-architecture)에는 같은 깨진 조각 3건이 복사되어 있습니다.
① 소속 없는 회전 애니메이션 파편, ② 동작 축소 블록에 잘못 들어간 배치 규칙, ③ 선택자만 남기고 조기 종료된 인쇄 규칙(은하 숨김 소실)입니다.
세 건 모두 공통 블록 안에 있으므로, 링크 교체 시 함께 사라집니다.

- **sample**: 고유 데모 스타일과 교육용 주석만 남기고, 공통 블록을 링크로 교체합니다. "공통 규칙은 deck-base.css에 있다"는 안내 주석을 추가합니다.
- **dx-vs-ax-automation**: 위 새 구조로 다시 작성합니다.
- **design-ax-transition**: 공통 블록을 링크로 교체합니다.
- **integrated-architecture**: 세 단계로 수리합니다. 먼저 깨진 한글 문장을 역변환(인코딩 왕복)으로 되살리고, 소실 글자는 앞뒤 문맥으로 채웁니다. 깨진 문장은 깨진 채로 추가된 것이라 저장 기록에 원본이 없습니다. 다음으로 슬라이드 묶음을 조기에 닫아버린 태그 오류를 고쳐 뒷부분 14장을 복구합니다. 마지막으로 두 벌로 중복된 스타일을 정리하고 공통 블록을 링크로 교체합니다. 이 자료만의 형광색 스타일은 그대로 둡니다.
- **ai-agent-skills-philosophy**: 공통 디자인에 편입합니다. 테마 링크보다 앞에 있던 이 자료 고유의 스타일 블록을 모든 링크 뒤로 옮깁니다. 이 순서 교정으로 제목 대문자 오류가 함께 풀립니다. 모서리 장식과 은하 배경 요소, 관련 스크립트를 추가합니다. 자료 고유의 요약 상자와 배치 스타일은 남깁니다. 두 번 들어간 화면 넘침 방지 블록은 한 번으로 정리합니다.

### 4. 검증 방법

구현 후 로컬 서버를 띄우고 브라우저 자동화 도구(Playwright)로 확인합니다.
합격 기준은 항목별로 다음과 같습니다.
- 다섯 자료 각각: 콘솔 오류 0건, 첫 화면이 어두운 배경으로 렌더링.
- 짝 전환(4장): 상자가 새로 그려지지 않고 제자리에서 미끄러지며 이름 교체.
- 단계 공개: 클릭 순서대로 요소가 하나씩 등장, 조망 모드(Esc)에서 전부 표시.
- 인쇄(PDF 내보내기 경로): 빈 페이지 0장, 모서리 장식·은하 미출력, 잘린 슬라이드 없음.
- 인쇄(인쇄 메뉴 경로): 도형 선이 검정으로 출력, 상자 밖으로 삐져나온 내용 없음.
- 목록 페이지: dx 자료 카드 클릭 시 새 자료가 열림.
- integrated 자료: 전체 슬라이드 수가 복구되고 깨진 글자 0건.

## 의도적 범위 제외

- **dx 외 자료의 도형 색 재작성**: integrated(95곳), ai-agent(45곳), design-ax(37곳)의 직접 적은 색은 이번에 고치지 않습니다. 각 자료의 내용 수정은 별도 사이클이 안전합니다. 인쇄 색 한계는 알려진 상태로 남습니다.
- **reveal 플러그인 도입**: 코드 하이라이트 등 플러그인은 저장소에 없으며, 이번에도 추가하지 않습니다. 오프라인 자립성이 우선입니다.
- **목록 페이지(styles.css) 변경**: 자료 쪽 작업이므로 손대지 않습니다. 캐시 표식(?v=2)도 유지합니다.
- **opencode 결과의 기계 해석(JSON 파싱) 예시**: 출력 형식이 공식 문서에 없어 검증 불가. 싣지 않습니다.
- **성능 수치 인용**: 방법 간 속도 비교 수치는 공식 벤치마크가 없어 정성 표현만 씁니다.
- **slides.json의 날짜 변경**: 발표 등록일은 이력이므로 유지합니다. (설명 문구 갱신은 결정 19로 수행 목록에 있습니다.)
