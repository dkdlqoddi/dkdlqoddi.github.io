# Unknowns: DX vs AX Automation Code Review

## 1. Domain Unknowns (도메인 미지 영역)
- **난이도 순서의 논리적 개연성**: 사용자가 지시한 순서(4 ➔ 1 ➔ 2 ➔ 3) 즉, `subprocess + opencode` ➔ `HTTP 직접 호출` ➔ `OpenAI SDK` ➔ `Langchain` 순서가 슬라이드 내에서 어떻게 "설정 난이도"와 "기능 범위" 측면에서 점진적으로 확장되는지로 설득력 있게 설명될 수 있는가?
  - *해소 방안*: `subprocess`는 가장 직관적인 CLI 래핑(비개발자도 쉬움)이고, `HTTP`는 프로그래밍의 기초이며, `OpenAI SDK`는 전용 라이브러리 학습이 필요하고, `Langchain`은 아키텍처(체인, 메모리) 전반을 이해해야 하는 "가장 어려운" 추상화 단계로 서사를 재구성합니다.

## 2. Platform/Environment Unknowns (환경 미지 영역)
- **실행 가능한 코드의 한계**: 실제 발표 자료 코드 블록(`index.html` 내 `<pre><code>`)에 작성되는 코드가 로컬 환경 변수 설정이나 더미 서버 응답 없이도 완전히 "실행 가능한" 느낌을 주려면 어떻게 해야 하는가?
  - *해소 방안*: 주석(`#`)을 활용하여 필수 환경 변수(`os.environ`) 세팅이나 가상의 API 엔드포인트를 명시하고, `print()` 결과가 어떻게 출력될지 주석으로 달아두어 독자가 코드 블록만 보고도 실행 결과를 완벽하게 유추할 수 있도록 작성합니다.

## 3. Implementation Unknowns (구현 미지 영역)
- **비교표(마지막 슬라이드)의 일관성**: 슬라이드 순서가 4-1-2-3으로 바뀌면, 마지막 "4가지 방법 비교" 슬라이드의 SVG 표도 이 순서에 맞게 재배열되어야 하는가?
  - *해소 방안*: 당연히 재배열되어야 합니다. SVG `<g class="fragment">` 태그의 위치와 텍스트 라벨(Row 1 ~ 4)을 바뀐 순서에 맞게 Y좌표 및 렌더링 순서를 조정하여 인지적 부조화를 방지합니다.
