# 발표자료 랜딩 페이지 요구사항 (예시 발표자료 1개 제작 포함)

- 날짜: 2026-07-23
- 상태: 확정
- 관련 문서: [Unknown Unknowns 문서](2026-07-23-landing-page-unknowns.md)

## 요청 배경

이 저장소는 발표자료를 웹 화면으로 보여주는 용도다. GitHub Pages라는 무료 웹 공개 기능이 붙어 있어, main 브랜치에 올리면 곧바로 https://dkdlqoddi.github.io 에 공개된다. 지금은 저장소가 비어 있다. 여러 발표자료로 안내해 주는 첫 화면(랜딩 페이지)이 필요하다. 이동 흐름 검증을 위해 예시 발표자료 1개 제작도 이번 작업 범위에 포함한다.

## Unknowns 4분면

| 분면 | 항목 |
|---|---|
| Known Knowns (명시된 요구사항) | 랜딩에서 여러 발표자료로 이동. 발표자료는 각자 다른 디렉터리에 보관. 발표자료마다 테마와 애니메이션을 따로 선택. 랜딩은 흰 바탕에 검정을 더한 우주 느낌(실물 우주복·우주왕복선 이미지는 금지). 모던한 최신 HTML 감각. |
| Known Unknowns (답이 필요한 질문) | 랜딩 형태, 목록 관리 방식, URL 구조, 카드 표시 정보, 예시 발표자료 포함 여부 — 5개 모두 인터뷰로 해소됨. |
| Unknown Knowns (인터뷰로 드러난 암묵적 선호) | 관리 부담 최소화 성향(다섯 질문 모두 가장 간단한 추천안 선택). 빌드 도구 없는 구성 선호(자체 해소로 확정). 화면 문구는 한국어. |
| Unknown Unknowns (미지 영역 — blindspot-pass 대상) | 예시 발표자료에서 reveal.js를 불러오는 방식(CDN인지 저장소 직접 포함인지 — 랜딩에는 reveal.js를 넣지 않음). GitHub Pages의 Jekyll 자동 변환 부작용. 모바일 화면과 접근성. 첫 화면 로딩 성능. 새 발표자료 추가 절차의 문서화. |

## 확정 요구사항

1. 랜딩 페이지는 일반 웹페이지로 만든다. 슬라이드 도구(reveal.js)의 전환·등장 애니메이션 느낌만 가져온다. (질문 1 답변)
2. 발표자료 목록은 목록 파일(JSON) 하나로 관리한다. 새 발표자료는 이 파일에 항목 하나를 추가하면 랜딩에 나타난다. (질문 2 답변)
3. 발표자료는 `slides/` 디렉터리 아래 발표별 폴더에 둔다. 폴더 이름은 영문 소문자와 하이픈만 쓴다(예: `intro-to-git`). 공유 링크는 `https://dkdlqoddi.github.io/slides/intro-to-git/` 모양이 된다. (질문 3 답변 + 자체 해소)
4. 랜딩의 발표자료 카드에는 제목, 발표 날짜, 한 줄 설명을 보여준다. 목록 파일의 각 항목에는 표시용 3개 정보와 이동 대상 폴더 이름을 함께 적는다. 카드를 누르면 그 폴더 주소로 이동한다. (질문 4 답변)
5. 예시 발표자료 1개를 reveal.js로 만들어 `slides/` 아래에 포함한다. 이동 흐름 검증과 새 발표자료 제작의 본보기 역할을 한다. (질문 5 답변)
6. 랜딩 테마는 흰 바탕에 검은색을 더한 구성이다. 우주 공간에 있는 흰 우주복·우주왕복선의 "느낌"만 살린다. 실제 우주복이나 우주왕복선 그림·사진은 넣지 않는다. (최초 요청)
7. 발표자료마다 테마와 애니메이션을 독립적으로 선택할 수 있어야 한다. 랜딩은 발표자료 내부 구현에 관여하지 않고 주소(URL)로만 연결한다. (최초 요청)

## 자체 해소 (질문 없이 증거로 결정한 사항)

- 기술 구성: 빌드 도구 없는 순수 HTML/CSS/JS. 근거: GitHub Pages는 정적 파일을 그대로 제공한다. 랜딩 하나에 빌드 체계를 얹는 것은 과잉이다.
- 화면 문구 언어: 한국어. 근거: 사용자의 대화 언어.
- 접근성 기본: 운영체제의 "움직임 줄이기" 설정(prefers-reduced-motion)을 존중해 애니메이션을 줄인다.
- 발표 폴더 이름 규칙: 영문 소문자와 하이픈만 사용. 근거: 한글·공백 폴더는 주소가 퍼센트 기호로 깨져 보여 공유 링크로 부적합하다.

|---|---|---|
| 랜딩 페이지를 어떤 형태로 만들까? (일반 웹페이지 / reveal.js 슬라이드 자체 / 풀스크린 섹션 전환형) | 모던 웹페이지 | 랜딩의 전체 구조를 결정. 랜딩에는 reveal.js 라이브러리를 넣지 않게 됨. |
| 발표자료 목록을 랜딩이 어떻게 알게 할까? (목록 파일 / HTML 직접 작성 / 자동 생성) | 목록 파일(JSON) 하나 | 데이터와 화면을 분리. 카드 그리기는 자바스크립트가 담당. |
| 발표자료 디렉터리를 어디에 둘까? (slides/ 아래 / 루트 바로 아래) | slides/ 아래 | 공유 URL 모양 확정. 한번 공유되면 바꾸기 어려운 공개 계약. |
| 카드에 어떤 정보를 보여줄까? (제목만 / 제목+날짜+설명 / +태그) | 제목+날짜+한 줄 설명 | 목록 파일에 적을 항목(스키마) 확정. |
| 예시 발표자료 1개를 같이 만들까? (포함 / 랜딩만) | 예시 1개 포함 | 작업 범위에 reveal.js 샘플 발표자료 1개 추가. |

## 미해결 질문

- 예시 발표자료의 reveal.js를 CDN(외부 서버)에서 불러올지, 저장소에 직접 넣을지. 인터넷 없는 발표장에서의 동작이 갈린다. 랜딩은 reveal.js를 쓰지 않으므로 해당 없음. — blindspot-pass 대상
- GitHub Pages의 Jekyll 자동 변환을 명시적으로 꺼야 하는지(.nojekyll 파일). — blindspot-pass 대상
- 발표자료가 수십 개로 늘었을 때의 정렬 기준과 화면 구성. — 후속 결정(지금은 최신순 정렬로 시작)
