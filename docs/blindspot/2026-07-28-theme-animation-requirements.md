# 테마 및 애니메이션 개선 요구사항

- 날짜: 2026-07-28
- 상태: 초안
- 관련 문서: 없음

## 요청 배경

사용자는 현재 깃허브 페이지로 호스팅되는 발표자료 프로젝트의 테마와 애니메이션이 나쁘다고 느낍니다. 다른 깃허브 페이지 프로젝트들을 참고하여 기존보다 훨씬 낫고 보기 좋은 테마와 부드러운 애니메이션을 적용하기를 원합니다. 

## Unknowns 4분면

| 분면 | 항목 |
|---|---|
| Known Knowns (명시된 요구사항) | 현재 프로젝트의 테마와 애니메이션을 타 프로젝트를 참고하여 개선한다. 인쇄 지원(Print-safe) 및 접근성(Motion-safe) 제약 조건은 기존 규칙대로 반드시 준수한다. |
| Known Unknowns (답이 필요한 질문) | 구체적으로 어떤 프로젝트를 참고할 것인지, 구형 브라우저 호환성을 어디까지 보장할 것인지. |
| Unknown Knowns (인터뷰로 드러난 암묵적 선호) | 기존 CLAUDE.md의 무채색 제한을 명시적으로 해제하고 강조 색상을 허용하길 원함. 외부 네트워크 의존 없이 오프라인 지원을 계속 유지하길 원함. 부드럽고 우아한 시네마틱 화면 전환 스타일(View Transitions API 및 Reveal.js 전환 효과 활용)을 선호함. |
| Unknown Unknowns (미지 영역 — blindspot-pass 대상) | 화려한 색상과 시네마틱 전환을 오프라인 자원만으로 구현할 때 생길 수 있는 파일 용량 한계. 기존 문서들의 CSS 구조를 변경할 때 발생할 수 있는 레이아웃 깨짐 현상. |

## 확정 요구사항

1. 기존 CLAUDE.md의 무채색(monochrome) 제한 규칙을 의도적으로 예외 처리(override)하여, 시선을 끄는 강조 색상을 테마에 허용한다. (인터뷰 근거: "기존 제약을 풀고 시선을 끄는 강조 색상을 새롭게 허용한다.")
2. 오프라인 지원 규칙을 엄격히 유지하며, 테마에 쓰이는 모든 폰트나 이미지는 프로젝트 내부에 직접 포함시킨다. (인터뷰 근거: "오프라인 지원 규칙을 유지하고 모든 리소스를 프로젝트 내부에 직접 포함시킨다.")
3. 애니메이션은 View Transitions API와 Reveal.js의 부드러운 전환 효과를 조합하여 우아한 시네마틱 스타일을 구현한다. 단, prefers-reduced-motion 설정 시 즉각 정지되는 기존의 Motion-safe 규칙은 반드시 지킨다. (인터뷰 근거: "부드럽고 우아하게 화면이 전환되는 시네마틱 스타일을 원한다.")

## 인터뷰 기록

| 질문 | 답변 | 아키텍처 영향 |
|---|---|---|
| 무채색 규칙을 풀고 강조 색상을 허용할 것인가? | 기존 제약을 풀고 강조 색상을 새롭게 허용한다. | 높음 (전체 디자인 변수 재정의) |
| 폰트나 요소를 추가할 때 오프라인 지원 규칙을 유지할 것인가? | 오프라인 지원 규칙을 유지하고 모든 리소스를 내부에 직접 포함시킨다. | 높음 (용량 제약 및 에셋 도입 방식 결정) |
| 새로운 애니메이션은 어떤 느낌이길 원하는가? | 부드럽고 우아하게 화면이 전환되는 시네마틱 스타일을 원한다. | 중간 (전환 효과 CSS 구성 방식 결정) |

## 미해결 질문

- 타 프로젝트 중 구체적으로 벤치마킹하고 싶은 특정 디자인이나 레퍼런스 페이지가 있는지 여부.
