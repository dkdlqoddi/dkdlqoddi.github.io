# Work Report: 현실적인 제약사항(블로커) 추가

## 1. 개요
* **목표:** 완벽해 보이는 3가지 아키텍처 대안을 가로막는 현실적인 VWP망 인프라의 한계와, 사내 LLM의 성능적 제약을 프레젠테이션에 추가하여 "개발 서버 증설"이라는 명확한 결론 도출.

## 2. 세부 변경 사항
1. **제약사항 1: VWP망 인프라 고갈**
   - 5개의 VWP 서버 랙을 SVG 인포그래픽으로 시각화. 4대는 GAIA가 점유 중(빨간색), 1대는 과부하(주황색/경고 배지) 상태임을 직관적으로 표현하여 Docker를 띄울 여력이 없음을 강조했습니다.
2. **제약사항 2: 100 RPM 제한 & Timeout**
   - 사내 모델 API의 한계를 보여주기 위해 게이지 바(Gauge) UI를 추가하고, 짧은 시간에 요청이 몰릴 경우 Timeout이 발생함을 시각화했습니다.
3. **제약사항 3: DS Assistant 4종 모델 비교**
   - Gemma4, GLM 5.2, Kimi V3, DeepSeek V4 4가지 모델의 추론 성능, 한글 이해도, 컨텍스트 창, 응답 속도를 점수 및 직관적인 아이콘(🚀빠름, 🐢느림)으로 비교하는 테이블을 삽입했습니다.
4. **결론 교체**
   - 기존의 단순한 '테스트 과제' 슬라이드를 들어내고, 이 모든 한계를 극복하기 위해선 궁극적으로 **"VWP망 개발 서버 추가 구매(증설)"**가 필요하다는 강력한 요청사항으로 결론을 바꾸었습니다.
