## 목적과 배경

이 저장소는 발표자료를 웹 화면으로 보여주는 공간이다. GitHub Pages라는 무료 서비스가 연결되어 있다. 이 서비스는 저장소의 파일을 그대로 웹사이트로 공개해 준다. main 브랜치에 파일을 올리면 몇 분 안에 https://dkdlqoddi.github.io 주소에 반영된다.

지금은 저장소가 비어 있어 접속해도 아무것도 나오지 않는다. 이번 작업으로 두 가지를 만든다. 첫째는 발표자료들을 안내하는 첫 화면(랜딩 페이지)이다. 둘째는 본보기가 될 예시 발표자료 1개다.

첫 화면의 분위기는 흰 바탕에 검정을 더한 우주 느낌이다. 아주 작은 점 입자와 얇은 선, 눈금 같은 추상 디테일로 표현한다. 실제 우주복이나 우주왕복선 그림·사진은 넣지 않는다.

## 결정사항

| # | 결정 | 근거 |
|---|---|---|
| 1 | 변환 도구 없이 순수 HTML/CSS/JS 파일로 만든다. | GitHub Pages는 정적 파일을 그대로 제공한다. 첫 화면 하나에 빌드 도구는 과잉이다. |
| 2 | 저장소 루트에 `.nojekyll` 파일을 두어 자동 변환기(Jekyll)를 끈다. | 변환기가 reveal.js 파일 속 특수 문구를 오해해 배포를 통째로 실패시킬 수 있다. |
| 3 | 발표자료는 `slides/` 아래 발표별 폴더에 둔다. 폴더 이름은 영문 소문자와 하이픈만 쓴다. | 공유 링크가 `https://dkdlqoddi.github.io/slides/발표이름/` 모양으로 고정된다. 서버가 대소문자를 구분하므로 소문자 통일이 안전하다. |
| 4 | 발표자료 목록은 `slides.json` 파일 하나로 관리한다. 항목마다 제목, 날짜, 한 줄 설명, 폴더 이름을 적는다. | 새 발표마다 항목 하나만 추가하면 첫 화면에 자동 반영된다. (사용자 선택) |
| 5 | 슬라이드 도구 reveal.js 6.0.1 사본을 `vendor/` 폴더에 넣는다. 기본은 모든 발표자료가 이 한 사본을 함께 쓴다. 다른 버전이 필요한 발표만 자기 폴더에 개별 사본을 둘 수 있다. | 인터넷 없는 발표장에서도 슬라이드가 열려야 한다. (사용자 선택) |
| 6 | 동봉하는 슬라이드 테마는 white와 black 2종만 넣는다. | 이 2종만 글꼴을 파일 안에 내장해 오프라인에서도 완전하다. 다른 테마는 쓰는 발표가 생길 때 추가한다. |
| 7 | 첫 화면 카드는 화면에 들어올 때 등장 효과를 재생한다. 구현은 화면 진입 감지 기술(IntersectionObserver)을 쓴다. | 이 기술은 모든 주요 브라우저에서 동작한다. 최신 대안은 Firefox가 아직 지원하지 않는다. |
| 8 | 페이지 사이 부드러운 전환(View Transitions)은 장식으로만 얹는다. 이동 자체는 일반 링크로 한다. | 미지원 브라우저에서는 그냥 평범하게 이동되어 아무것도 깨지지 않는다. |
| 9 | 운영체제의 "움직임 줄이기" 설정이 켜져 있으면 모든 움직임을 멈춘다. 입자와 전환 효과도 포함이다. | 멀미·어지럼을 느끼는 사용자를 위한 접근성 기본기다. 일부 효과만 남기는 안은 남길 기준이 모호해 기각했다. |
| 10 | 첫 화면 글꼴은 Pretendard를 쓴다. 첫 화면에만 적용한다. | 한국어 화면의 사실상 표준 글꼴로, 정밀한 계기판 느낌에 맞는다. 발표자료 글꼴은 각자 자유다. |
| 11 | 잘못된 주소를 받아 줄 404 안내 페이지를 둔다. | 존재하지 않는 주소로 온 방문자를 첫 화면으로 되돌린다. GitHub 기본 404 화면은 영어이고 첫 화면 링크가 없어 기각했다. |
| 12 | 예시 발표자료의 내용은 "새 발표자료 추가 방법" 안내로 채운다. | 예시가 곧 사용 설명서가 되어 문서가 이중으로 늘지 않는다. |
| 13 | 내부 작업 폴더(`.claude/`, `docs/`)가 웹 주소로도 열리는 것을 받아들인다. | 저장소가 이미 공개라 새로 노출되는 비밀이 없다. |
| 14 | 저장소에 연결된 서브모듈은 지금처럼 공개 저장소, HTTPS 주소를 유지한다. | 비공개나 SSH 주소로 바꾸면 사이트 배포 전체가 실패한다. README에 경고를 남긴다. |

## 검토한 대안과 트레이드오프

| 결정 | 채택안 | 기각안 | 기각 이유 |
|---|---|---|---|
| 첫 화면 형태 | 일반 모던 웹페이지 | reveal.js 슬라이드 자체 / 풀스크린 섹션 전환형 | 목록 탐색에는 자유로운 스크롤이 낫다. 슬라이드형은 방향키 조작을 강제한다. (사용자 선택) |
| 목록 관리 | `slides.json` 파일 하나 | HTML 직접 수정 / GitHub Actions 자동 생성 | HTML 수정은 실수로 화면을 깨기 쉽다. 자동 생성은 설정이 늘고 설명은 결국 수동 입력이다. (사용자 선택) |
| reveal.js 로딩 | 저장소에 사본 포함 | CDN(외부 서버)에서 불러오기 | 발표장에 인터넷이 없으면 CDN 슬라이드는 통째로 깨진다. (사용자 선택) |
| 사본 구조 | 전체 발표가 한 사본 공유 | 발표마다 사본 각자 보관 | 발표마다 수백 KB가 중복된다. 특정 발표가 다른 버전을 원하면 그 폴더에만 따로 넣으면 된다. |
| 자동 변환기 | 끈다(`.nojekyll`) | 켠 채 유지 | 변환기가 슬라이드 파일을 훼손하는 위험만 있고 이득이 없다. |
| 등장 애니메이션 | 화면 진입 감지(IntersectionObserver) | 최신 스크롤 연동 CSS 단독 사용 | 최신 방식은 Firefox에서 전혀 재생되지 않는다. 진입 감지는 어디서나 된다. |
| 페이지 전환 | 일반 링크 + 지원 브라우저만 부드러운 전환 | 한 페이지 안에서 화면만 갈아끼우는 방식(SPA) | 정적 발표 허브에 불필요한 복잡도가 든다. 링크 공유·새로고침도 불리해진다. |
| 첫 화면 글꼴 | Pretendard(외부 CDN, 버전 고정) | 시스템 기본 글꼴 | 기본 글꼴은 기기마다 인상이 달라진다. 첫 화면은 온라인 전용이라 외부 글꼴 부담이 없다. |
| 입자 표현 | 순수 CSS 점 입자 | canvas(그림 그리는 프로그래밍 기술) | 점 100여 개에 canvas는 과잉이다. CSS만으로 배터리·성능 부담 없이 충분하다. |
| 내부 폴더 노출 | 노출 수용 | 게시 대상을 docs/ 폴더로 격리 | 격리 방식은 발표자료 주소 모양을 깨뜨린다. 내부 기획 문서가 오히려 게시 대상이 되는 역효과도 있다. |

## 동작 방식

### 방문자가 보는 흐름

1. 방문자가 https://dkdlqoddi.github.io 에 접속한다. 첫 화면이 열린다.
2. 첫 화면의 스크립트가 목록 파일 `slides.json`을 읽는다.
3. 목록의 항목 하나가 카드 하나로 그려진다. 카드에는 제목, 발표 날짜, 한 줄 설명이 보인다.
4. 카드는 최신 발표가 먼저 오도록 정렬된다.
5. 화면을 내리면 카드들이 차례로 떠오르듯 등장한다.
6. 카드를 누르면 `slides/폴더이름/` 주소로 이동한다. 그 폴더 안의 발표자료가 열린다.
7. 발표자료는 reveal.js로 작동한다. 방향키나 화면 넘김으로 슬라이드를 넘긴다.
8. 존재하지 않는 주소로 들어오면 404 안내 페이지가 나온다. 첫 화면으로 가는 링크를 보여준다.

### 새 발표자료를 추가하는 흐름

1. `slides/` 아래에서 예시 발표자료 폴더를 복사한다. 새 폴더 이름은 영문 소문자와 하이픈으로 짓는다.
2. 복사한 폴더 안의 내용(슬라이드 본문, 테마, 전환 효과)을 원하는 대로 고친다.
3. `slides.json`에 제목, 날짜, 한 줄 설명, 폴더 이름을 담은 항목 하나를 추가한다.
4. main 브랜치에 올리면 몇 분 안에 공개된다. 방문자에 따라 목록 반영이 최대 10분 늦을 수 있다.

### 만들어질 파일 구조

아래는 이번 작업 후 저장소의 모습이다. 괄호는 각 파일의 역할이다.

```
index.html          (첫 화면)
styles.css          (첫 화면 꾸밈: 우주 테마, 입자, 카드)
main.js             (목록 읽기, 카드 그리기, 등장 효과)
slides.json         (발표자료 목록 파일)
404.html            (잘못된 주소 안내)
.nojekyll           (자동 변환기 끄는 빈 파일)
README.md           (추가 절차 안내, 서브모듈 경고)
vendor/reveal.js/   (슬라이드 도구 사본: 엔진, white·black 테마, LICENSE)
slides/
  sample/           (예시 발표자료: "새 발표자료 추가 방법")
    index.html
```

## 의도적 범위 제외

- 검색, 태그, 페이지 나눔: 지금은 발표자료가 1개뿐이라 판단 근거가 없다. 10개 도달 시 재검토한다.
- 어두운 화면 모드(다크 모드): 흰 바탕이 이 화면의 정체성이라 만들지 않는다.
- 발표 영상 등 대용량 파일 대응: 이번 발표자료에는 영상이 없다. 파일당 100MiB 제한도 있어 별도 방법이 필요하다.
- 방문 통계 도구: 요구사항에 없다.
- 목록 자동 생성(GitHub Actions): 수동 목록 파일로 충분하다. 검색·태그와 같은 시점(발표자료 10개 도달 시)에 재검토한다.
- 발표자료 내부 공통 디자인 강제: 발표마다 테마 자유가 요구사항이다. 랜딩은 주소로만 연결한다.
- 스크롤 연동 고급 연출: Firefox가 지원하지 않아 보류한다.
- 검색 엔진 최적화 심화(사이트맵 등): 개인 발표 허브라 기본 정보 태그만 넣는다.
