## 스캔 원본 요약

### conventions

(1단계 requirements-interview에서 실행한 스캔 결과를 재사용)

- 덱은 CSS 변수 없이 랜딩 팔레트를 리터럴 hex로 복제 (#0e0e0e/#53565c/#ddd), 헤어라인은 이미 #dddedb vs #ddd로 미세하게 갈라짐
- 배경은 body가 아닌 `.reveal-viewport`(특이성 0,1,0)에 걸어야 함 — body 선택자는 진다
- 오버라이드 가능한 테마 변수는 --r-* 27개, white/black 동일 세트
- 표지 관례: eyebrow → h2 → small 부제 → tiny "날짜 · 이름", 구분자 가운뎃점
- slides.json 스키마는 4필드, 여분 키는 조용히 무시됨, date 정규식 `^\d{4}-\d{2}-\d{2}$`
- reveal 6.0.1 plugin 폴더 부재, autoAnimate·data-background-*는 코어 기능이라 사용 가능
- 발표자 이름 "우재율"은 저장소 전체에서 덱 표지 1곳뿐
- 실물 우주선 이미지 금지·모노크롬 무악센트는 2026-07-23 랜딩 요구사항의 확정 결정이었음 (이번에 일부 대체)

- 404: styles.css 미참조 자기완결, 리터럴 9곳, 저장소 유일의 반전 채움 버튼, noindex
- black.css: white.css와 9개 변수만 다름, 링크·컨트롤 파랑(#42affa), uppercase는 동일하게 존재(취소 오버라이드 유지 필요)
- 파비콘: 4개 문서 완전 동일 data URI (흰 타일 + 검은 링 + 검은 점)
- 랜딩 반전 비용 낮음: 색 토큰 4개 + 리터럴 1곳(rgba 그림자) — 단 graphite 대비와 hairline 과대비 재조정 필요

### edge-cases

- black.css도 uppercase — 대문자 취소 오버라이드는 테마를 바꿔도 그대로 필요
- 대비 계산 (WCAG 상대휘도): #53565c on #0e0e0e = 2.62:1 (11곳 전부 미달), #dddedb 반전 시 14.29:1 과대비, 4.5:1 최소 무채색은 #7b7b7b, 3:1은 #5f5f5f
- 인쇄: reveal 6은 ?print-pdf 시 reveal-print+print-pdf 클래스 동시 부여, 일반 인쇄에서 레거시 블록이 통째로 적용 — 커스텀 도형(.box/.link/.steps)은 색 강제 대상 밖이라 백지 인쇄됨
- 별 42개는 뷰포트 무관 고정 개수 — 4K에서 밀도 1/4, 모바일에서 과밀. 덱 .slides 안에 넣으면 scale(1.48 @1080p)이 vw/vh 좌표에 곱해져 배치 붕괴 + overflow:hidden에 잘림 → .reveal 형제 fixed 레이어가 안전
- file:// 폰트: 코드에 CORS 강제 장치는 없으나 @font-face fetch는 사양상 항상 CORS 모드 — 벤더의 base64 인라인이 회피책의 증거
- 덱 배경은 JS 부착 클래스 의존 — JS 실패 시 흰 배경 + 흰 글자 = 백지. color-scheme 선언 저장소 전체 0건
- reduce 함정: 0.01ms 재생은 fill-mode 있는 애니메이션을 끝 상태에 고정 — 키프레임 중립 설계 또는 개별 animation:none 필요. SMIL은 미차단
- 오류 문구 3종은 .mono → graphite 상속 (토큰 수정 시 자동 반전), 빈 목록이면 카운트 공백
- 접근성 관례 두 갈래: 장식은 aria-hidden 한 줄 / 의미 도형은 3종 세트. 별·우주선은 전자. 404 포커스 링·호버가 리터럴 검정이라 반전 필수
- 장식 레이어는 예외 없이 fixed — absolute 우주선은 가로 스크롤 유발
- 고칠 날짜/이름 문자열은 정확히 2곳 (slides.json:4, 덱 표지 :108). docs/blindspot 과거 날짜는 이력이므로 유지

### domain

- file:// 폰트: Firefox는 상위 디렉터리 차단(의도된 동작, INVALID 종결), Chrome/Safari는 문서 진술 엇갈림 — 100% 안전한 방법은 base64 내장뿐 (Quarto embed-resources가 같은 이유로 채택). 대가: 용량 +33%, CSS 파싱 블로킹
- crossorigin 속성: 폰트 preload에는 필수지만 file://에서는 성공 근거가 없음 — preload 자체를 넣지 않는 것이 안전
- 프로젝터: 검정은 스크린에서 짙은 회색 (1% 누광), 어두운 방=다크 / 밝은 방=라이트가 실무 경험칙
- 다크 팔레트: 배경 #121212급 근검정, 고강조 텍스트 흰색 87%(≈#DEDEDE) — halation 완화. 본문 최소 24pt/제목 36pt, 굵기 medium(500) 최적
- 흰 번쩍임 방지 3종: meta color-scheme(모든 CSS보다 먼저) + :root color-scheme + html 배경색. theme-color는 브라우저 UI만 바꾸는 부가 요소
- 크로스 도큐먼트 뷰 트랜지션: Safari 18.2/Chrome 126+, Firefox 미지원 — color-scheme이 실제 방어선
- reveal 6 인쇄: 쿼리 ?view=print (구 ?print-pdf 호환), 플러그인 불필요, 코어가 print-color-adjust:exact 강제 → 검은 덱은 전면 검정 PDF
- Pretendard Variable: @font-face에 font-weight:45 920 필수(누락 시 WebKit 굵기 오렌더링), format('woff2-variations'), font-variation-settings는 쓰지 말 것
- macOS 흰 글자 굵어 보임: -webkit-font-smoothing은 macOS 밖 무효 — 굵기 한 단계 낮추기가 실효 대책
- font-display: 동봉·오프라인 상황에서는 block이 적합 (swap은 발표 중 폰트 교체 연출, optional은 100ms 초과 시 시스템 폰트 확정). base64 내장이면 사실상 무관
- 한글 조판: 본문 자간 −0.02em, 강조 −0.03em 통용. keep-all은 사실상 필수 + overflow-wrap 동반 필요
