# Requirements Interview: Interactive 3D Galaxy & HUD UI

- 날짜: 2026-07-29
- 목적: 시점 전환, 행성 시각화 및 라벨-선 연결 UI, 은하수 다색화 요구사항 구체화

## 분석된 제약사항 및 엣지케이스 (자체 해소)
- **외부 라이브러리 추가 불가 (OrbitControls 미사용)**: `file://` 환경에서 작동하는 구버전 `three.min.js`만 벤더링된 상태이므로, 카메라 시점 제어는 외부 플러그인(OrbitControls) 없이 순수 삼각함수와 마우스(터치) 이벤트 리스너를 결합하여 직접 구현합니다.
- **연결선(Line) 드로잉 방식**: 3D 공간의 행성과 2D 화면의 HTML 버튼 사이를 잇기 위해 HTML `<svg>` 오버레이를 사용하여 프레임마다 `<line>` 요소를 업데이트하는 방식이 가장 성능이 좋고 깔끔합니다.
- **행성 확대 로직**: 현재 은하수는 하나의 거대한 점 뭉치(Point Cloud) 렌더링입니다. 마우스 호버 시 특정 행성을 키우기 위해, 발표 자료와 연결되는 "주요 행성"들은 3D 구체(Sphere) 메쉬로 별도 생성하여 스케일 애니메이션이 가능하도록 분리합니다.

## 확인이 필요한 질문 (Q1 ~ Q2)

**Q1. 카메라 시점 변경 방식**
은하수를 바라보는 시점을 변경할 때, "마우스를 클릭하고 드래그(Drag)"해야만 화면이 돌아가게 할까요? 아니면 마우스를 "화면 위에서 움직이기만(Hover/Move)" 해도 카메라가 마우스를 따라 부드럽게 시점을 바꾸게 할까요? (드래그 방식은 정적이고 덜 어지럽지만, 마우스 무브 방식은 더 게임 같은 역동적인 느낌을 줍니다.)

**Q2. 행성과 버튼의 배치 디자인 (선 연결)**
행성과 버튼을 선으로 연결할 때, 버튼(발표자료)들이 행성 주변 무작위 방향으로 펼쳐지는 것이 좋나요, 아니면 화면의 좌/우측 가장자리에 깔끔하게 정렬되고 그곳에서부터 행성으로 선이 뻗어나가는 형태(마치 영화의 HUD 패널처럼)가 좋나요?
