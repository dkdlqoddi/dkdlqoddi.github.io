## 용어 보충

요구사항 문서의 용어에 더해 이번 조사에서 새로 나온 말이다.

- **셸** — 사람이 친 명령을 받아 실행해 주는 프로그램이다.
- **비대화형 셸** — 사람이 지켜보지 않는 상태로 도는 셸이다. 시작 설정 파일을 읽지 않는다. 그래서 사람이 직접 쓰는 터미널에서 되던 명령이 여기서는 안 된다.
- **멱등성** — 같은 것을 두 번 세 번 실행해도 결과가 같은 성질이다. 실행 대리 프로그램은 실패하면 자동으로 다시 한다. 그래서 이 성질이 필요하다.
- **허용 목록** — 미리 정해 둔 것만 실행하게 하는 방식이다. 글자만 맞춰 보기 때문에 보안 방어로는 약하다. 실수를 막는 장치로 보는 것이 맞다.
- **스크립트 계약** — 스크립트가 지켜야 할 약속이다. 인자를 몇 개 받는지, 무엇을 남기면 성공인지 같은 것이다.
- **종료 코드** — 프로그램이 끝나면서 남기는 숫자다. 0은 성공을 뜻한다. 나머지 숫자에 뜻을 정해 두면 실패 원인을 구분할 수 있다.
- **입구** — 중개 서버에 접근하는 통로다. 지금은 통로가 둘이다.
- **3단 직렬** — 세 시스템이 한 줄로 이어진 구조다. 이번 조사에서 실제 구조는 이것이 아님이 밝혀졌다.
- **정본 표기** — 여러 문서에서 이미 쓰고 있는 공식 표기다. 새 표기를 만들면 기존 문서와 연결이 끊긴다.

## 조사 범위 정정

요구사항 문서는 참고 저장소를 세 개로 적었다. 실제로 조사해 보니 관련 저장소가 하나 더 있었다. 지식 파이프라인을 담당하는 저장소다. 네 번째 저장소도 비공개임을 확인했다. 그래서 이 문서는 네 저장소를 조사 대상으로 삼는다. 공개 기준은 네 저장소에 똑같이 적용한다.

|---|---|---|---|---|
| 1 | 실제로 운영 중인 설정에서 어느 폴더가 열려 있고 어느 폴더가 막혀 있는가. | 그 설정 파일은 저장소에 없다. 배포하는 곳마다 다르게 쓰도록 되어 있다. 코드만으로는 확인할 수 없다. | 결정됨 — 확인하지 않는다. 발표에서 폴더 개수나 비율 같은 숫자를 말하지 않는다. 경계의 성격만 말한다. | 실제 운영 설정을 손볼 때 담당자가 확인한다. |
| 2 | "가상작업공간(VWP) 서버"가 정확히 어느 시스템을 가리키는가. | 중개 서버 쪽 저장소에는 그 말이 한 번도 나오지 않는다. 다른 저장소 문서도 이 항목을 아직 못 풀었다고 기록해 두었다. 코드로는 결론이 나지 않는다. | 결정됨 — 발표에서도 정본 표기인 가상작업공간(VWP)을 그대로 쓴다. 어느 시스템인지는 발표자가 구두로 보충한다. | 저장소 문서들의 용어를 맞출 때. 새 이름을 쓰려면 공개 기준을 다시 검토해야 한다. |
| 3 | 두 입구 중 어느 쪽을 실제 운영 경로로 삼을 것인가. | 운영 정책의 문제다. 코드가 답하지 않는다. | 확인 필요 없음 — 발표에서 연결이 어떻게 보호되는지 단정하지 않는다. 그러면 지금 정하지 않아도 된다. | 발표 원고를 확정할 때 발표자가 정한다. |
| 4 | 담당자가 낸 절차와 스크립트를 어디로 어떻게 접수할 것인가. | 지금은 접수 창구가 없다. 원안대로 "절차를 글로 내려 공유"하는 것이 목적이므로 창구 없이도 발표는 성립한다. | 결정됨 — 발표에서 "접수 방식은 함께 정하자"로 열어 둔다. | 발표 후 첫 제출이 들어오기 전까지. |
| 5 | 요청을 전체에 한 번에 보낼 것인가. 아니면 선도 조직 두세 곳과 먼저 해 볼 것인가. | 조사에서는 선도 조직 먼저가 낫다는 근거가 나왔다. 다만 이것은 요구사항에 없던 새 의제다. 조직 운영 방식은 발표자가 정할 몫이다. | 결정됨 — 이번 발표자료에는 넣지 않는다. | 발표 원고 확정 시 발표자가 정한다. |
| 6 | 청중이 현재 어느 정도까지 알고 있는가. | 확인할 방법이 없다. 발표자만 아는 사실이다. | 확인 필요 — 배경 설명의 깊이가 이 답에 달려 있다. | 발표 원고를 읽어 보며 발표자가 조절한다. |

## 스캔 원본 요약

아래는 기술 근거다. 공개 기준에 따라 저장소 이름과 경로는 역할 이름으로 바꿔 적었다. 보안 항목은 여기서도 제외했다.

### 관례 (conventions)

- 실행 대리 프로그램 쪽에 이미 스크립트 계약이 있다. 인자는 입력과 출력 두 개. 성공은 종료 코드 0 + 비어 있지 않은 출력 파일. 최대 3회 재실행되므로 멱등 필수. 컨트롤러는 종료 코드와 출력 파일 존재 두 가지로만 판정한다.
- 판정 신호는 출력 **첫 줄**에 고정 문구로 온다. 성공과 실패를 정해진 문자열로 구분하고, 인증 실패는 별도 문구로 구분해 재시도 없이 즉시 중단시킨다.
- 종료 코드에 계층이 있다. 0은 전체 성공, 1은 일부 실패, 2는 즉시 중단이다. 다른 저장소는 3까지 쓴다.
- 환경변수 관용구 세 가지가 확립되어 있다. 필수 변수는 실행 전에 내보내고 없으면 즉시 종료한다. 선택 변수는 기본값을 허용한다. 공유 설정 묶음은 "읽어들이기 전용" 파일로 분리한다.
- 작업 디렉터리 규약이 저장소마다 정반대다. 한쪽은 스크립트가 스스로 자기 폴더로 이동한다. 다른 쪽은 저장소 루트 실행을 암묵 전제로 한다. 중개 서버 쪽은 절대 경로만 허용하며, 그 이유는 경로가 붙임표로 시작해 옵션으로 오인되는 것을 막기 위함이다.
- 형상관리 도구, 권한 전환 명령, 그룹 전환은 네 저장소에 0건이다. 단순 미구현이 아니라 현재 배치가 구조적으로 막는다. 명령이 셸 없이 인자 배열로 실행되고, 서비스가 고정 계정·고정 그룹으로 돌며 권한 상승도 막혀 있기 때문이다. 나중에 실제로 돌리려면 실행 통로를 여는 결정이 따로 필요하다.
- "안전"에 해당하는 규칙이 이미 9가지 구현되어 있다. 기본 거부, 비밀 경로 우선 차단, 셸 미사용, 경로 재검사, 기동 시 설정 대조, 타임아웃과 응답 상한, 원자적 쓰기, 컨트롤러 측 경로 제한, 승인 관문이다.
- 되돌리기 절차는 없다. 대신 "되돌릴 수 없음"을 문서 상단 경고로 노출하는 것이 이 저장소들의 관례다.
- 담당자용 가이드는 관리자 등록 가이드와 배포 점검표 두 형태로만 있다. 업무 담당자가 절차나 스크립트를 제출하는 창구는 없다.
- 저장소마다 규모와 자동 테스트 보유 여부가 다르다. 자세한 내용은 비공개 파일로 넘겼다.

### 유사 기능 (similar-features)

- 네 저장소 모두 완성된 한국어 설명 문서를 갖고 있다. 혼자 열리는 HTML 설명 문서도 세 개 있다. 셋 다 발표 엔진을 쓰지 않는 단일 HTML이다.
- 망 분리 정본 표기는 "사무망(Office)"과 "가상작업공간(VWP)"이다. "폐쇄망"은 인터넷이 끊긴 사내 환경을 가리키는 별개 축의 말이다. 사내 패키지 미러, 빌드 도구 반입 같은 맥락에서 쓰인다.
- 이미 동작하는 사례가 넷 있다. 개발망에서 AI 코딩 도구와 중개 서버의 연결을 실제로 확인했다. 지식 파이프라인은 모델이 필요 없는 부분 전체를 실측 완료했고 회귀 테스트가 상시 돈다. 기존 사내 자동화의 설정을 REST 창구로 열어 AI 도구가 조회하고 바꿀 수 있게 한 사례가 있다. 조회 명령은 예시 설정에 15개가 들어 있다. 다만 실제 업무용 등록은 0건이다.
- 네 저장소 모두 이 발표 저장소와 같은 공유 도구를 쓰고 있다. 같은 라이프사이클 산출물이 쌓여 있다.
- 담당자용 요청 항목이 이미 문서에 흩어져 있다. 등록 대상 채우기, 허용 폴더 지정, 프록시 확인 항목, 평가셋 채우기, 토큰 발급과 교체 주기다. 다만 "Domain 담당자"라는 호칭은 0건이다.
- 성숙도가 저장소마다 다르다. 구현이 끝난 곳도 있고 아직 검증 단계인 곳도 있다. 저장소별 세부는 비공개 파일로 넘겼다.
- 문서와 코드가 어긋난 곳이 있다. 폐기된 설정 방식 설명이 아직 남아 있고, 중개 서버 주소 표기가 저장소마다 다르다.
- 발표에 바로 쓸 만한 결정 기록이 있다. 작은 모델에서는 반복 제어를 모델 밖으로 빼야 한다는 근거가 대표적이다. 단계 성공률이 95%여도 8단계면 전체 성공률이 66%로 떨어진다는 계산이다.

### 연결 지점 (integration-points)

- 실제 구조는 3단 직렬이 아니다. 중개 서버 하나에 클라이언트 둘이 붙는 형태다. API 서버는 중개 서버의 하류가 아니라 상류 클라이언트이며, 도구 17개를 REST로 다시 노출한다. 대상은 중개 서버에 직접 붙을 수 없는 PC다.
- 프로토콜은 HTTP 기반 스트리밍이다. 서버가 클라이언트를 되부르는 코드는 없다. 요청과 응답 한 방향이다.
- 실행 대리 프로그램은 중개 서버에 원격 주소로 붙는다. 로컬 프로세스를 띄우지 않는다. 접속 열쇠가 없으면 연결이 거부된다.
- 도구는 정확히 17개다. 읽기 6, 쓰기 2, 미리 등록한 작업 6, 분석 1, 정책 조회 2.
- 에이전트별 권한이 비대칭이다. 네 에이전트가 도구를 와일드카드 없이 개별 열거한다. 어떤 에이전트는 파일 읽기 도구가 아예 거부되어 있고, 등록된 조회 명령으로만 내용을 가져온다. 어떤 에이전트는 중개 서버 도구를 전부 거부한다. 순서와 재시도와 성공 판정은 모델이 아니라 셸 스크립트가 한다.
- 중개 서버가 자원에 닿는 방법은 넷뿐이다. 자기 호스트의 파일, 미리 등록한 명령 실행, 데이터베이스 조회, 사내 API 호출이다. 데이터베이스와 API 등록은 현재 비어 있다. 데이터베이스 조회는 조회문만 등록할 수 있고 한 문장만 허용된다. 사내 API는 읽기 방식만 허용되고 자동 이동을 따라가지 않는다.
- 망 분리는 코드에 이름으로 존재하지 않는다. 환경 스위치 세 개로만 드러난다. 분석 도구는 특정 환경이 아니면 즉시 실패하고, 그 이유가 "개발망에서 외부 모델에 닿을 수 없음"이라고 주석에 적혀 있다.

### 예외 상황 (edge-cases)

- 허용 목록은 2단이다. 도구 17개와 관리자가 등록한 작업이다. 조회 명령 15개가 예시 설정에 들어 있다. 데이터베이스와 API 등록은 기본이 0건이다.
- REST 중계 쪽은 아무것도 차단하지 않는다. 도구 17개를 그대로 통과시킨다. 차단은 전부 중개 서버 안에서만 일어난다. 따라서 "중개 서버가 제한한다"는 문장에서 제한 주체는 하나다.
- 읽기와 쓰기와 명령 실행은 각각 기본값이 다르다. 그 기본값이 실질적인 경계를 만든다. 구체적인 값은 비공개 파일로 넘겼다. 이 점이 발표에서 "제한적 접근"을 설명할 때 가장 조심해야 할 지점이다.
- 쓰기는 관리자가 열어 준 폴더에서만 가능하다. 삭제·제출·전송 도구는 없으므로 파괴적 동작은 한 종류뿐이다. 폴더 생성도 불가하고 크기 상한이 있다. 되돌리기 가능 여부는 비공개 파일로 넘겼다.
- 현재 등록된 명령은 전부 조회 명령이다. 발표에서는 "관리자가 등록한 것만 돌고 현재 등록분은 전부 조회 명령"이라고 말하는 것이 정확하다. 그 성질을 무엇이 보장하는지는 비공개 파일로 넘겼다.
- 경로와 주입 방어는 실재한다. 절대 경로 강제, 상위 이동 무력화, 바로가기 거부, 셸 미사용, 모든 인자에 정규식이나 열거 강제다.
- 무엇이 나가는지는 도구 인자를 준 사람이 결정한다. 출력 제한이 어떻게 걸려 있는지는 비공개 파일로 넘겼다.
- 타임아웃과 동시 실행 제한은 도구마다 다르게 걸려 있다. 자세한 내용은 비공개 파일로 넘겼다.

### 도메인 조사 (domain)

- 비대화형 실행에서 깨지는 원인이 여섯으로 수렴한다. 터미널 가정, 환경변수 미자립, 경로 미자립, 엄격 모드 미설정, 대화형 대기, 종료 코드 계약 부재다. 그중 시작 설정 파일이 비대화형에서 조기 종료되어 변수가 사라지는 것이 1순위 원인이다. 출처: 비대화형 셸 해설 문서, Bash 관례 정리.
- 권한 전환 명령은 현재 셸을 새 셸로 치환한다. 스크립트에서는 뒷줄이 실행되지 않는다. 해법 우선순위는 셋이다. 첫째, 그룹 전환 자체를 없애고 계정 설정이나 폴더 설정으로 해결한다. 둘째, 스크립트 선두에서 자기 자신을 다시 실행한다. 셋째, 단일 명령만 감싼다. 셋째 방법은 감싼 명령이 다른 셸에서 도는 함정이 있다. 출처: 그룹 전환 명령 매뉴얼.
- 허용 목록은 보안 경계가 아니다. 문자열 그대로 맞춰 보며 인자 수준 제약은 신뢰할 수 없다. 규칙 적용 순서와 자동 승인 옵션에도 함정이 있다. 구체적인 우회 형태는 비공개 파일로 넘겼다. 출처: 도구 권한 공식 문서.
- 에이전트 셸 권한의 실무 최소 집합은 일곱이다. 기본 거부, 승인 게이트 고정 목록, 예행 연습 우선, 되돌리기 경로 명시, 기록 남기기, 영향 범위 제한, 비밀 정보 비노출이다. 출처: 에이전트 셸 보안 해설, 되돌리기 설계 글.
- 도구 노출 시 공식 스펙의 필수 항목은 넷이다. 받은 열쇠를 그대로 전달하지 않기, 세션을 인증에 쓰지 않기, 중계형이면 클라이언트별 동의와 정확 문자열 검증, 로컬 서버는 전송 방식으로 접근 제한이다. 출처: 프로토콜 공식 보안 문서, OWASP 점검표.
- 재사용 절차의 신뢰성은 세 가지에서 갈린다. 설명문 품질, 자유도 매칭, 스크립트가 오류를 직접 처리하는가다. 설명은 3인칭으로 무엇과 언제를 함께 쓴다. 취약한 작업일수록 자유도를 낮춘다. 참조는 한 단계 깊이만 둔다. 상수에는 근거 주석을 단다. 출처: 재사용 절차 작성 지침.
- 조직 확산이 실패하는 이유는 다섯이다. 수용 기준 없는 요청, 강제로 밀어붙이기, "실행 가능"의 오해, 검수 부재, 소유권과 수명 부재다. 대응은 제출 양식과 자동 검증과 합격 예시를 함께 배포하는 것이다. 출처: 플랫폼 실패 사례 글, 2025년 개발 생산성 보고서.
- "실행 가능"의 실무 정의가 제시되어 있다. 깨끗한 새 세션에서 예행 연습이 부작용 없이 통과하고, 연속 두 번 실행 결과가 같고, 종료 코드가 문서와 일치하는 것이다.
