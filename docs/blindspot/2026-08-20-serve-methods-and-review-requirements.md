# opencode serve 예시 승격 + 전체 발표자료 리뷰 요구사항

- 날짜: 2026-08-20
- 상태: 확정
- 관련 문서: docs/blindspot/2026-08-19-dx-ax-redesign-unknowns.md (선행 조사), docs/blindspot/seminar-accuracy-behavior-implementation-notes.md (사실 검증 관례), docs/2026-08-seminar-script.md (발표 대본). 이번 사이클 관례 스캔의 근거는 아래 "스캔 근거 요약" 절에 수록.

## 요청 배경

팀 세미나 1부 덱(slides/dx-vs-ax-automation)은 사내 LLM에 연결하는 방법을 4가지로 소개한다. 사용자는 opencode를 HTTP 서버로 띄워 두고(`opencode serve`) 밖에서 부르는 예시 추가를 원한다. 첫째 예시는 그 서버에 HTTP 요청을 직접 보내는 것이다. 둘째 예시는 같은 서버를 Python 라이브러리로 부르는 것이다. 아울러 저장소의 발표자료 전체 점검(리뷰)도 요청했다.

## 스캔 근거 요약 (관례 렌즈, 2026-08-20)

- [C1] 1부 덱은 평면 14장이고, 코드 슬라이드 4장(방법 1~4)은 5단 골격(미터, 숨은 설명, 미니 그림, 코드, 한 줄 요약)을 공유한다. 근거: slides/dx-vs-ax-automation/index.html:384-545.
- [C2] 자동 모프(auto-animate) 짝은 4↔5장 한 곳뿐이다(index.html:168, :221). 그 사이에 끼우지 않으면 모프는 안전하다.
- [C3] "4가지/네 가지" 표기는 아래 "확정 요구사항 4"의 체크리스트 위치에 하드코딩되어 있다.
- [C4] 발표 대본(docs/2026-08-seminar-script.md)은 장 번호·제목·화살표 횟수·총 장수·쪽수를 명시한다(:3, :15, :42-58, :164, :169).
- [C5] 코드 블록 관례는 `<pre><code>`이며 11~12줄·54자 이내다. 복사 버튼은 code-copy.js가 자동 부착한다.
- [C6] 슬라이드 높이 상한은 두 가지다 — 단계 공개(fragment)가 있는 장 660px, 없는 장 700px (선행 문서 해소항목 24).
- [C7] 덱 간 링크는 디렉터리 주소뿐이라 슬라이드 삽입이 링크를 깨지 않는다(index.html:658-659).
- [C8] 선행 도메인 조사: opencode 본체는 pip로 설치할 수 없다(설치 경로는 curl 스크립트·npm·brew). Python 클라이언트 라이브러리의 존재 여부는 별개 사안으로 미조사다.

## Unknowns 4분면

| 분면 | 항목 |
|---|---|

## 확정 요구사항

1. 방법 5 슬라이드를 새로 만든다 — `opencode serve`를 띄우고 터미널에서 curl로 HTTP 요청을 보내는 예시. (근거: 요청 원문 + 답변 "새 방법 5·6으로 승격")
2. 방법 6 슬라이드를 새로 만든다 — 같은 서버를 Python 라이브러리(requests)로 호출하는 예시. (개정 2026-08-20: 공식 SDK opencode-ai는 실재하지만 2025-08 알파에서 정지했고, 로컬 실측에서 응답을 파싱하지 못했다. 그래서 "실재하면 그것을 쓴다"는 원래 조건을 버리고 requests로 확정한다 — 근거는 unknowns 문서 해소 4.) 방법 5(터미널 확인)와의 차별점은 프로그램 통합 — 답변 텍스트 추출을 보여 준다. SDK 상태는 대본 예상 질문에 근거와 함께 기록한다.
3. 두 슬라이드는 방법 1~4와 같은 격의 "새 방법"이다. 부록이나 하위 전개가 아니다. (근거: 인터뷰 답변)
4. "4가지/네 가지/4단계" 표기를 6 기준으로 전면 갱신한다. 체크리스트:
   - slides/dx-vs-ax-automation/index.html — :7 meta 설명, :101 표지 부제, :117 여정 지도 문구, :343 7장 제목, :344 숨은 그림 설명, :345 계단 aria-label, :379 호출/위임 캡션, :386·:424·:467·:510 미터 aria-label과 칸 span(4장 전부), :550 비교표 제목, :551 숨은 표 설명, :552 비교표 aria-label.
   - slides.json:17 설명 문구.
   - docs/2026-08-seminar-script.md — :3 구성, :15 쪽수, :25·:39·:40·:54 "4가지" 문구, :164·:169 압축 경로의 장 번호.
   - 화면에 안 보이는 숨은 설명(visually-hidden)과 aria-label도 빠뜨리지 않는다.
5. 미터는 6칸(①~⑥)으로 넓히고 기존 4장의 미터도 함께 바꾼다. 미터의 축 이름은 "추상화"에서 "연동 방법"(진행 순서)으로 바꾼다. 이유: ⑤ HTTP 직접 호출은 ④ 위임보다 추상화가 낮아, 추상화 축으로는 사다리가 단조 증가하지 않는다.
6. 계단 그림(:345)은 ①~④ 추상화 사다리를 유지하고, ⑤·⑥은 ④와 같은 높이의 "위임 구간" 확장으로 그린다. 캡션(:379)은 "①→③ 호출 / ④→⑥ 위임"으로 바꾼다.
7. 비교표는 4행에서 6행으로 늘린다. 비교표 장은 fragment가 있으므로 높이 660px 이내를 지킨다.
8. 발표 대본을 갱신한다. 체크리스트: 1부 장수 14→16, 유인물 쪽수 합계 41→43, 신규 2장의 대본(도입·조작 큐·촌평) 추가, 신규 2장 시간 배정(각 0:45 — 기존 장 시간은 유지, 총 45:00), 압축 경로의 장 번호와 머리글 수치(절감량·결과 시간) 재계산, 첫 압축 경로에 "방법 5·6 훑기" 항목 추가. (개정 2026-08-20: 시간 배분 방침 확정 — unknowns 해소 8.)
9. 전체 리뷰 범위: 등록 덱 4종 + 템플릿(sample) + 랜딩(index.html·main.js·styles.css) + slides.json + 공유 자산(slides/shared/, scripts/galaxy3d.js). 핀 고정된 vendor/는 제외.
10. 리뷰에서 발견한 것 중 규칙 위반(CLAUDE.md·deck-base 규칙), 기능 결함(렌더·링크·접근성·인쇄·모션), 사실 오류, 덱 간 일관성 어긋남은 이번 브랜치에서 즉시 수정한다. (근거: 답변 "발견 즉시 전부 수정")
11. 순수 미학 취향 변경(테마·배색 재설계 등)은 즉시 수정 대상이 아니다. 보고서에 제안 목록으로만 남긴다.
12. 선행 사이클이 "차기 사이클로 미룸"으로 확정했던 항목(예: 다른 덱의 인쇄 색 복구)은 이번 리뷰에서 재평가한다. 결함으로 확인되면 10번 기준에 따라 수정한다.
13. 예시 코드는 로컬에 설치된 opencode 1.17.18 실제 서버로 실행해 검증한 뒤 싣는다. (근거: 이 저장소의 사실 검증 관례)
14. 작업은 피처 브랜치에서 한다(main 직커밋 금지, CLAUDE.md 규정). 머지는 사전 퀴즈 통과 후에만 한다.

## 자체 해소 결정 (질문하지 않고 근거로 확정)

- 방법 5·6의 순서: 5 = curl HTTP 직접 호출, 6 = Python 라이브러리. 요청 원문의 나열 순서를 따랐다.
- 도구 분담: 5는 curl, 6은 공식 라이브러리 또는 requests. 라이브러리 부재 시에도 두 장이 중복되지 않도록 도구를 갈랐다.
- 표현 형식: 2부의 터미널 재생(.term) 형식이 아니라 1부 코드 슬라이드 5단 골격을 쓴다. 방법 1~4의 형제 슬라이드이므로 같은 골격이어야 형제로 읽힌다.
- 미터 축 재정의(확정 5): 되돌릴 수 있는 표현 결정이므로 구현 중 질문 없이 확정하고 여기 기록한다.
- 슬라이드 고정 주소(id 앵커) 도입: 하지 않는다. 공유·인용 계획이 확인되지 않았고, 저장소 최초 선례를 만드는 결정이므로 필요할 때 별도로 한다.
