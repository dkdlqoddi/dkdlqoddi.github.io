## 요청 배경

발표 자료 `slides/ai-agent-skills-philosophy`는 인공지능 코딩 도구와 스킬 10가지를 소개합니다.
이 자료는 제어 장치(harness)라는 단어를 설명 없이 사용합니다.
사용자는 이 단어가 낯선 청중도 그림으로 개념을 이해하기를 원합니다.
요청은 두 가지입니다.
첫째, 덱 전체 리뷰입니다.
둘째, 새 시각화 추가입니다.
새 시각화의 내용은 다음과 같습니다.
제어 장치가 없는 언어모델(LLM)은 낼 수 있는 결과물의 폭이 넓습니다.
제어 장치를 더할수록 그 결과물 폭이 좁아집니다.

리뷰의 수행 시점을 명확히 합니다.
덱 리뷰(코드 검사)는 이 요구사항 단계에서 이미 1차 수행되었습니다.
발견된 결함의 수정은 이번 작업의 산출물에 포함됩니다.
종합 리뷰 결과는 마지막 단계의 작업 보고서(work-report)에 담습니다.
별도의 리뷰 전용 보고서는 만들지 않습니다.

## 확정 요구사항

1. 작업 범위(할 일의 경계)는 "새 시각화 추가 + 발견 결함 수정"이다. 근거: 인터뷰 답변 "시각화 추가 + 결함 수정".
2. 수정할 결함은 다음 세 가지다.
   - 결함 1 (인쇄 대비 저하): 도형 색을 직접 지정한 곳이 45곳이다(fill, stroke 속성 기준). 직접 지정한 색은 인쇄 때 검정으로 복구되지 않는다. 흰 종이에 밝은 청록이 그대로 남아 읽기 어렵다.
   - 결함 2 (화살촉 정의 공유): 화살촉 정의(marker)가 oh-my-opencode 슬라이드의 그림 한 곳에만 있다. 나머지 슬라이드들이 그 정의를 참조한다. 슬라이드 사이에 숨은 의존이 생긴 상태다.
   - 결함 3 (그림 상세 설명 누락): 모든 그림에 접근 이름(aria-label)은 있다. 그러나 낭독기용 시각 은닉 상세 설명 문단(visually-hidden)이 없다.
3. 새 시각화는 표지 바로 다음, 도구·스킬 소개 10장보다 앞에 둔다. 근거: 인터뷰 답변 "커버 직후 도입부".
4. 표현 기법은 두 장 사이 자동 모핑(auto-animate)이다. 결과물 폭의 축소는 첫째 장에서 둘째 장으로 넘어갈 때 1회 일어난다. 근거: 인터뷰 답변 "두 장 모핑".
5. 둘째 장의 내용은 "일반 원리 + 실제 예시 결합"이다. 일반 원리 층은 둘째 장 안에 정지 상태로 그려진다. 층은 4개다: 지시문(시스템 프롬프트), 도구 제한, 정해진 작업 절차(스킬), 검증 루프. 실제 예시는 fablize로 든다. 근거: 인터뷰 답변 "일반 원리 + 실제 예시 결합" + 개정 1·2.
6. 모핑 구현은 인쇄(PDF)와 동작 축소 환경에서 의미가 깨지지 않아야 한다. 이 조건은 질문 전제에 포함되어 사용자가 승인했다.
7. 슬라이드 수는 11장에서 14장이 된다(시각화 2장 + 마무리 장 1장 추가). 덱 목록 파일(slides.json)은 수정할 필요가 없다. 근거: 개정 3.

## 개정 이력 (2026-08-20, 사각지대 점검 결과 반영)

1. 개정 1: 일반 원리 층을 3개에서 4개로 확장했다. 추가된 층은 검증 루프다. 결정 주체: 사용자. 근거는 unknowns 문서 해소 항목 1번이다.
2. 개정 2: 실제 예시 스킬을 ponytail 후보에서 fablize로 확정했다. 결정 주체: 자체 해소. 근거는 unknowns 문서 해소 항목 6번이다.
3. 개정 3: 마무리 장을 추가하기로 확정했다(13장 → 14장). 결정 주체: 사용자. 근거는 unknowns 문서 해소 항목 3번이다.
4. 개정 4: 슬라이드 번호 주소(#/N)의 2칸 밀림을 수용하기로 확정했다. 결정 주체: 사용자. 근거는 unknowns 문서 해소 항목 2번이다.
5. 개정 5: 부수 정리 항목을 하나 추가했다. 사용처가 0곳인 스타일 규칙 2개를 삭제한다. 결정 주체: 자체 해소. 근거는 unknowns 문서 해소 항목 19번이다.
6. 개정 6: 화면에 쓸 용어를 "하네스"로 확정했다. 이 문서의 "제어 장치(harness)" 표기는 낯선 독자용 설명이고, 슬라이드에는 "하네스"로 적는다. 결정 주체: 자체 해소. 근거는 unknowns 문서 해소 항목 16번이다.
7. 개정 7 (2026-08-20 구현 중): 도구 슬라이드 10장의 요약 상자 잘림 수정을 범위에 추가했다. 원래부터 있던 결함으로 실측 확인되었다. 결정 주체: 사용자(병합 전 확인 질문에서 "이번에 범위 확장" 선택). 수정 방법: 고정 높이 제거, 요약 글자 축소, 상자 폭 확대. 근거는 구현 노트 02:20 항목이다.

## 자체 해소 항목 (질문 없이 근거로 결정)

1. 새 슬라이드는 저장소 정본 규약을 따른다. 정본 규약은 네 가지다: 정본 도식 클래스(class="diag"), 글자색을 따라가는 색 체계(currentColor), 시각 은닉 설명 문단(visually-hidden), 다각형(polygon) 화살촉. 근거: `slides/shared/deck-base.css`와 `slides/sample/`이 이를 정본으로 명시함.
2. 원본 덱 설계 문서는 "추상적 아이콘과 은유 위주의 디자인"을 기각했다(explainer 23행). 이번 시각화는 은유가 아니라 작동 구조를 그린다. 작동 구조란 입력, 가능한 결과물 폭, 층별 제약을 뜻한다. 따라서 기존 선호와 충돌하지 않는다. 또한 신규 명시 요청이 과거 기각 결정보다 우선한다.
3. 원본 요구사항의 "1페이지에 1개 스킬" 규칙은 도구·스킬 소개 장에 적용되는 규칙이다. 새 개념 슬라이드 2장은 도구 소개 장이 아니므로 적용 대상이 아니다. 도구·스킬 장의 규칙 자체는 그대로 유지된다.
4. 결함 1의 수정 방법: 직접 지정한 색을 정본 클래스(.accent, .danger 등)로 치환한다. 도형의 모양과 배치는 바꾸지 않는다. 전면 재설계는 사용자가 선택하지 않았다.
5. 결함 2의 수정 방법: 기존 슬라이드의 화살촉 참조(marker)를 다각형(polygon) 화살촉으로 교체한다. 근거: 저장소 정본 규약이며, 교체하면 슬라이드 사이 의존이 사라진다.
6. 개념 슬라이드는 기존 도구 슬라이드의 요약 상자 형식("철학:" 3항목)을 따르지 않는다. 그 형식은 도구 1개를 소개하는 틀이기 때문이다.
