## 목적과 배경

반도체 설계 팀원들에게 인공지능 에이전트 연동 시스템의 전체 구조를 쉽게 전달해야 합니다. 오픈코드, API 서버, MCP 서버, 가상 작업망(VWP) 등 4가지 구성 요소가 어떻게 연결되는지 순서대로 보여줍니다.

가상 작업망 내부에서 담당자들이 에이전트를 위해 설정해야 할 핵심 작업 3가지를 명확히 안내합니다. 담당자들이 툴 설정값 정의, 스크립트 준비, 로그 분석 기준을 어떻게 마련해야 하는지 설명합니다. 이를 통해 복잡한 설계 업무를 에이전트가 스스로 돕는 형태로 변환하는 과정을 교육하는 것이 핵심 목적입니다.

## 결정사항

| # | 결정 | 근거 |
|---|---|---|
| 1 | 슬라이드 분할 애니메이션 적용 | 한 화면에 많은 정보를 쏟아내지 않고 순차적으로 이해를 돕기 위함입니다. |
| 2 | 가로 형태의 단계형 알약 디자인 사용 | 담당자 작업 3단계의 절차적 성격을 직관적으로 강조하기 위함입니다. |
| 3 | 스크립트 권한을 `sg` 명령어로 부여하도록 안내 | 환경 초기화로 인한 에이전트 무한 멈춤 사고를 막기 위함입니다. |
| 4 | 사용자 환경 존중(P4CONFIG 유지) 명시 안내 | 기존 작업 공간 덮어쓰기 위험을 사용자에게 확실히 인지시키기 위함입니다. |
| 5 | 라이선스 에러 분기 명시 안내 | 용량 한계와 통신 장애를 구분하여 에이전트의 상황 대처력을 높이기 위함입니다. |
| 6 | 물리 검증(DRC) 에러 분기 명시 안내 | 에이전트가 자체 수정할 수 있는 단순 위반의 한계선을 명확히 긋기 위함입니다. |

## 검토한 대안과 트레이드오프

| 결정 | 채택안 | 기각안 | 기각 이유 |
|---|---|---|---|
| 시스템 구조 배치 | 각 요소가 순차적으로 등장하며 연결 | 한 번에 전체 구조를 모두 표시 | 정보 과부하가 발생하고 논리적 연결 흐름을 따라가기 어렵습니다. |
| 도메인 작업 나열 | 가로로 긴 알약 모양 단계 형태 | 바둑판 모양의 카드형 나열 | 각 역할이 독립적인 것이 아니라 순서대로 진행되는 절차임을 보여주기에 부적합합니다. |
| 스크립트 권한 지침 | 단일 명령 실행이 가능한 `sg` 권한 부여 | 디렉터리 전체에 상속 속성 부여 | 단일 작업에만 권한을 부여하는 것이 추후 문제 추적에 훨씬 투명합니다. |
| 물리 검증 자동화 지침 | 단순 위반만 자동 수정, 나머진 승인 대기 | 가능한 모든 에러를 에이전트가 자동 수정 시도 | 복잡한 반도체 회로 오류를 기계가 임의 수정하는 치명적인 위험을 방지합니다. |

## 동작 방식

발표 화면에서 전체 시스템 뼈대가 순서대로 하나씩 나타납니다. 오픈코드에서 시작된 요청이 여러 서버를 거쳐 가상 작업망에 도달하는 선이 그려집니다.

다이어그램 밑으로 알약 모양의 가로 단계 3개가 차례대로 드러납니다. 첫 번째 단계는 툴 설정값 정의 원칙을 시각적으로 안내합니다. 두 번째 단계는 멈춤 사고를 막고 기존 환경을 존중하는 스크립트 작성법을 보여줍니다. 세 번째 단계는 라이선스나 검증 로그를 보고 에이전트가 후속 결정을 내리는 기준을 안내합니다.

시각장애인용 낭독기는 다이어그램 직전의 보이지 않는 글을 읽습니다. 이를 통해 그림을 보지 않고도 전체 구조를 미리 파악할 수 있습니다.

## 의도적 범위 제외

- 실제 백엔드 에이전트 코드나 인프라 스크립트 구현은 제외합니다. 본 프로젝트는 순수한 웹 발표자료 저장소이며 실제 코드 구현은 시스템 아키텍처 범위를 벗어나기 때문입니다.
- 복잡한 입체 모형이나 외부 동영상 미디어 요소는 제외합니다. 외부 인터넷 연결 없이 오프라인에서 구동되고 종이에 인쇄할 수 있어야 하므로, 순수 HTML/SVG 도형과 CSS 기반의 기본 애니메이션 규칙만 사용합니다.
