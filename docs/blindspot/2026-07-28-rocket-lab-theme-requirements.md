# Rocket Lab 기하학적 구조 이관 및 렌더링 개선 요구사항

- 날짜: 2026-07-28
- 상태: 확정
- 관련 문서: 없음

## 요청 배경

사용자가 슬라이드의 한글 렌더링 버그(안티앨리어싱 누락) 수정을 요청하며, 이를 계기로 Rocket Lab의 투자자 발표자료 구조 및 테마 특징을 차용하여 슬라이드를 개편해 달라고 요청했습니다.
*(참고: 마우스 반응형 은하 배경 애니메이션 기능은 이 문서의 범위를 초과하므로 다른 문서에서 독립적인 작업 단위로 분리하여 다룹니다.)*

## Unknowns 4분면

| 분면 | 항목 |
|---|---|
| Known Knowns (명시된 요구사항) | 안티앨리어싱 버그 수정, 저장소 기본 규칙(다크 모노크롬 팔레트)을 유지하면서 Rocket Lab 스타일의 기하학적 배치 및 폰트 구조 차용 |
| Known Unknowns (답이 필요한 질문) | 1) 도입할 오픈소스 기하학적 산세리프 폰트(예: Montserrat)의 구체적인 파일 구성<br>2) 모노크롬 제약 내에서 Rocket Lab 특유의 느낌을 내기 위한 테두리 굵기 및 여백 CSS 사양 |
| Unknown Knowns (인터뷰로 드러난 암묵적 선호) | 외부 폰트 통신 제약 하에서도 영문 폰트 파일을 저장소에 직접 복사(벤더링)하여 사용함을 승인함 |
| Unknown Unknowns (미지 영역 — blindspot-pass 대상) | 모든 슬라이드 파일을 일괄 수정할 때 기존의 특수 슬라이드나 다이어그램이 깨지지 않게 보장하는 안전한 마이그레이션 방법 |

## 확정 요구사항

1. 기존 다크 흑백 테마의 **색상 규칙(모노크롬, 강조 색상 금지)은 엄격히 유지하되**, 그 위에서 Rocket Lab 발표자료와 유사한 기하학적 레이아웃(여백, 선 굵기, 폰트 비례 등)을 차용하여 모든 슬라이드 파일을 개편합니다.
2. 텍스트 렌더링 품질을 높이기 위해 화면 다듬기(안티앨리어싱) 처리가 저장소 내 모든 개별 슬라이드에 일괄 적용되어야 합니다.
3. 기하학적 산세리프 폰트인 **Montserrat** 오픈소스 폰트를 선정하여 저장소 내부에 파일로 직접 복사(벤더링)하고, 영문 텍스트에 최우선 적용되도록 폰트 스택을 구성합니다.
4. (범위 제외) 마우스 반응형 은하(Galaxy) 배경 애니메이션 개발은 본 요구사항 문서에서 배제하며 별도의 문서로 분리합니다.

## 인터뷰 기록

| 질문 | 답변 | 아키텍처 영향 |
|---|---|---|
| 외부 폰트 통신이 금지된 환경에서 영문 폰트를 어떻게 처리할지 여부 | 유사 오픈소스 폰트를 찾아 파일로 벤더링(저장소 복사)하여 영문에 적용 | 저장소 용량 증가 및 폰트 파일 직접 로딩에 따른 구조 변경 발생 |
| 테마 전면 개편 범위 | 기존에 만들어진 모든 슬라이드까지 전부 일괄 변경 | 단일 슬라이드 개편이 아닌 전체 슬라이드 파일 다수 수정 발생 |

## 미해결 질문
