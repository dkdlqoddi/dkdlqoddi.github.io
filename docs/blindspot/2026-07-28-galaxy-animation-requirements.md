# 마우스 반응형 은하수 배경 애니메이션 요구사항

- 날짜: 2026-07-28
- 상태: 초안
- 관련 문서: 없음

## 요청 배경

사용자가 발표자료와 첫 진입 화면의 배경에 마우스 움직임에 반응하는 은하수 애니메이션을 추가해 달라고 요청했습니다.
이전 작업에서는 디자인을 바꾸는 데 집중하느라 이 기능이 뒤로 미뤄져 있었습니다.
사용자는 여러 개의 은하가 동시에 화면에 떠다니며 마우스 주변에서 역동적으로 움직이는 효과를 원하고 있습니다.

## Unknowns 4분면

| 분면 | 항목 |
|---|---|
| Known Knowns (명시된 요구사항) | 수학 공식을 이용해 직접 그리기(외부 그림 금지), 마우스 위치에 반응하기, 어지럼증 방지(모션 저감) 켜짐 시 고정 화면 제공 |
| Known Unknowns (답이 필요한 질문) | 오프라인 환경에서 여러 문서에 똑같이 배경을 그릴 때 중복을 최소화하는 방법, 기기 성능 저하를 방어할 구체적인 입자 수 제한 기준 |
| Unknown Knowns (인터뷰로 드러난 암묵적 선호) | 배터리 소모가 발생하더라도 눈에 띄는 애니메이션 효과를 선호함, 랜딩 페이지와 모든 발표자료 화면에 일관되게 애니메이션이 깔리길 원함 |
| Unknown Unknowns (미지 영역 — blindspot-pass 대상) | 브라우저 성능 최적화 기법 및 모션 프레임레이트 안정화 방안 |

## 확정 요구사항

1. 첫 진입 화면(랜딩 페이지)과 모든 발표자료 화면의 배경에 마우스 움직임에 반응하는 은하수 애니메이션을 똑같이 띄워줍니다. (근거: "랜딩 페이지와 개별 발표자료 모두에 은하수 애니메이션을 띄워 주세요.")
2. 배터리 소모가 다소 발생하더라도 화면이 계속 움직이도록 허용하되, 목표 프레임 속도는 초당 30프레임(30fps) 및 파티클 개수를 최대 100개 이하로 제한하여 과도한 성능 저하를 방어합니다. (근거: "성능 저하와 배터리 소모를 조금 감수하더라도...")
3. 인터넷 연결 없이 언제 어디서든 동작하도록, 무거운 외부 그림 파일 대신 수학 공식과 코드만을 사용하여 도형을 그립니다. (근거: 기존 저장소 강제 규칙 유지)
4. 사용자가 운영체제 설정에서 어지럼증 방지(모션 저감)를 켜둔 경우, 애니메이션 동작을 멈추고 고정된 정지 화면만 보여줍니다. (근거: 기존 저장소 강제 규칙 유지)

## 미해결 질문

- 오프라인 환경에서 애니메이션 코드를 여러 슬라이드 문서에 중복 없이 어떻게 공통으로 적용할 것인가?
- 화면이 느려지지 않도록 브라우저 렌더링을 30fps 수준으로 안정화할 구체적인 최적화 코드는 어떻게 작성할 것인가?
