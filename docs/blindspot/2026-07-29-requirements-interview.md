# Requirements Interview: Codebase Review & Refactoring

전체 프로젝트 코드베이스(`HTML`, `CSS`, `main.js`, `galaxy3d.js`)를 꼼꼼히 리뷰한 결과, 오프라인 제약조건을 훌륭히 지키고 있으며 Three.js 메모리 누수 방지 처리도 잘 되어 있습니다. 하지만 **성능 최적화, 접근성, 그리고 모바일 사용성 측면에서 개선이 시급한 몇 가지 기술 부채(Technical Debt)** 를 발견했습니다.

다음 4가지 핵심 안건 중 우선적으로 해결하고 싶은 개선 사항을 선택해 주세요. (여러 개 선택 가능)

### 1. [성능 최적화] SVG 렌더링 프레임 드랍(Layout Thrashing) 방지
현재 `galaxy3d.js`의 `updateLabels()` 함수는 매 프레임(초당 60번)마다 `svgLayer.innerHTML`에 문자열을 때려 박아 SVG DOM을 통째로 갈아치우고 있습니다. 이는 브라우저의 파싱 및 레이아웃을 강제하여 심각한 렉(프레임 드랍)을 유발합니다.
- **제안**: 카드가 생성될 때 SVG 노드를 한 번만 만들어 두고, 매 프레임마다 `.setAttribute`로 좌표(`x1`, `y1` 등)만 가볍게 업데이트하도록 아키텍처를 변경할까요?

### 2. [접근성 개선] 화면 밖 발표자료 카드 키보드 탭 제어 (A11y)
카드가 카메라 뒤쪽(화면 밖)으로 넘어가면 투명도(`opacity: 0`)로 안 보이게 처리되지만, 여전히 DOM 상에는 존재하여 키보드 `Tab` 키로 포커스가 잡히고 스크린 리더기가 이를 읽어버리는 버그가 있습니다.
- **제안**: 카드가 화면 뒤로 넘어갈 경우 `visibility: hidden` (또는 `pointer-events: none`) 처리를 추가하여 접근성 트리에서 완전히 제외시킬까요?

### 3. [모바일 호환] 드래그(Orbit) 조작 방식 확장
현재 3D 은하수 시점 회전은 마우스 휠(가운데) 버튼(`event.button === 1`) 클릭으로만 동작합니다. 이로 인해 스마트폰, 태블릿 터치 사용자나 일반 노트북 트랙패드 사용자는 은하수를 전혀 돌려볼 수 없습니다.
- **제안**: 모바일 `touchstart`, `touchmove` 이벤트를 추가하고, 데스크톱에서도 일반 왼쪽 클릭(Left-click)으로 화면을 드래그할 수 있도록 조작성을 확장할까요?

### 4. [유지보수 향상] 카드 로딩 감지 방식 변경 (Polling -> Event)
`galaxy3d.js`는 카드가 로딩되었는지 확인하기 위해 0.5초마다 무한 반복하는 `setInterval` 타이머를 돌리고 있으며, `main.js`는 `IntersectionObserver`로 투명도를 제어하려 하지만 3D 캔버스 로직과 서로 충돌하고 있습니다.
- **제안**: 무식한 타이머(Polling)와 불필요한 Observer를 전부 제거하고, `main.js`가 카드를 다 그렸을 때 단 한 번만 이벤트를 던져 `galaxy3d.js`가 이를 깔끔하게 받아먹도록 동기화 로직을 리팩토링할까요?

---

위 4가지 항목 중 진행을 원하시는 번호를 말씀해 주시거나, "전부 다 진행해 줘"라고 말씀해 주시면 상세한 Implementation Plan을 세워 바로 착수하겠습니다!
