3. **"oh-my-opencode 아닌가요?"** — 저장소가 oh-my-openagent로 개명됐습니다. 저장소 설명에 'previously oh-my-opencode'라고 명시되어 있습니다.
4. **"Aider 요즘도 쓰나요?"** — 릴리스 속도가 느려져 저속 유지보수 상태입니다. 그래서 '현재 권장'이 아니라 'CLI 에이전트의 원형'으로 소개했습니다.

7. **"grill-me·fablize는 어디서 받나요?"** — 각각 mattpocock/skills(스킬 폴더), fivetaku/fablize 공개 저장소입니다. ponytail·blindspot-flow는 우리 환경에 이미 설치되어 있습니다.
8. **"폐쇄망에서도 이 자료가 열리나요?"** — 네. 폰트·라이브러리가 전부 저장소에 동봉되어 있어 file://로도 열립니다.
9. **"opencode 공식 Python SDK가 있지 않나요?"** — 있습니다(PyPI `opencode-ai`). 그러나 2025-08 알파(0.1.0a36)에서 갱신이 멈췄고, 요청·응답 형식이 현행 서버와 어긋나 로컬 1.17.18 실측에서 응답 필드를 읽지 못했습니다. 그래서 방법 6은 requests입니다. 참고로 JS/TS SDK(`@opencode-ai/sdk`)만 본체와 같은 버전(락스텝)으로 유지됩니다.
10. **"serve는 어느 폴더를 프로젝트로 보나요?"** — 공식 문서에 규정이 없습니다. 로컬 1.17.18 실측으로는 서버를 띄운 폴더였습니다(응답의 path.cwd). 작업할 저장소 폴더에서 띄우는 게 안전합니다. 같은 폴더에서 인스턴스를 여러 개 띄우면 세션 저장소를 공유해 간섭할 수 있으니, 한 서버에 세션 여러 개가 안전한 형태입니다.
11. **"serve를 팀 공용 서버에 올려도 되나요?"** — 기본이 무인증이고 셸 실행·파일 읽기 엔드포인트가 있어 위험합니다. 예전 버전에는 원격 코드 실행 취약점(CVE-2026-22812)도 있었습니다. 로컬 전용으로 쓰고, 밖으로 열어야 하면 `OPENCODE_SERVER_PASSWORD`를 반드시 설정하세요. 그리고 이 API는 안정성 보증 문구가 없고 소규모 업데이트에서 깨진 전례가 있으니 버전을 고정하세요.
12. **"완전 폐쇄망에서 serve가 되나요?"** — 밖으로 나가는 연결이 두 가지 있습니다: 모델 목록 조회(models.dev)와 LLM 호출 자체. 완전 에어갭은 아직 공식 지원이 없습니다(열린 기능 요청). 사내 LLM 연결은 방법 4에서 본 opencode.json의 provider 설정으로 합니다.

14. **"방법 5의 HTTP와 8장(공통 전제)의 HTTP는 같은 건가요?"** — 다른 경계입니다. 방법 5는 내 코드와 opencode 서버(127.0.0.1) 사이, 8장은 호출자와 사내 LLM 사이입니다. 조각 스트림(SSE)도 두 경계에 각각 따로 존재합니다. 프록시 환경에서 로컬 쪽을 NO_PROXY로 우회시키라는 opencode 공식 안내가 이 분리의 증거입니다(network 문서, 2026-08-19 확인).
