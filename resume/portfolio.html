01

모르는 도메인을 도서관과 지식 지도로 만들기사내 LLM 위키 · 논문 지식 베이스 · 사내 의미 검색 · 3계층 문서와 결정 기록

문제

반도체 설계 사인오프 흐름, EDA 도구, 팀의 SOP처럼 제가 모르는 도메인 지식이 코드보다 먼저 필요했습니다. 자료는 흩어져 있고, 에이전트에게 매번 다시 설명하면 컨텍스트가 낭비됩니다.

도구와 접근

원문(raw)은 불변으로 보존하고 Claude Code 스킬이 출처·개체·개념·주제 위키 마크다운을 유지합니다. Next.js 앱이 GraphRAG와 BM25 하이브리드 검색을 제공하고, 헤드리스 인제스트에는 권한 deny 목록을 걸어 문서 속 프롬프트 인젝션이 소스를 수정하지 못하게 했습니다. 코드베이스 쪽은 규칙·지도·명세 3계층 문서와 한 줄짜리 결정 기록으로 지식 지도를 유지합니다.

결과물

  • 사내 LLM 위키(커밋 120건, Next.js 16 + pnpm)와 개인용 custom-llm-wiki(Claude Code 스킬 /wiki-save · /wiki-ask, BM25 + e5-small 임베딩 하이브리드 검색, RAG 채팅).
  • 논문 PDF를 메타·요약·개념 노트로 양방향 추적하는 논문 지식 베이스(paper-review), 사내 LLM(Gemma 4)과 BGE-M3 임베딩·자체 호스팅 벡터 DB 기반 의미 검색 설계(cds-librarian).
  • 10명이 동시에 Claude Code로 개발할 저장소에서 ADR 66건·요구사항 137건을 3계층 문서로, 다시 결정 기록 표로 이관해 다시 묻지 않는 협업 체계 구축.

02

그 지식 위에 세운 프로그램: GAIA 2.0반도체 설계 사인오프 진행 추적 풀스택 대시보드 (2026-06 ~ 현재)

문제

설계 과제의 Task·Checklist 일정과 Run 검증 결과가 엑셀과 메일에 흩어져 있어 사인오프 진행을 한눈에 볼 수 없었습니다. 도메인 규칙이 자주 바뀌어 요구사항이 130건 넘게 쌓였습니다.

도구와 접근

Claude Code가 요구사항 인터뷰 → 명세 → 구현 → 변경 분석 → 머지 전 퀴즈까지 수행하는 하네스로 개발했습니다. 검증은 Playwright e2e·vitest·husky 게이트와 셀프호스팅 러너 2대 병렬 CI가 맡고, 사람은 PR 리뷰와 머지만 합니다.

결과물

  • Next.js 16 App Router 단일 앱, Prisma + PostgreSQL 모델 23개, Route Handler 41개, 모듈 19개, 커밋 850건 이상.
  • 마일스톤별 Score·추세 대시보드, 인라인 일정 편집 Task Gantt, SOP 체크 이행 화면, Run 파생 트리, react-konva floorplan 편집기, XLSX 적재·내보내기 SOP 워크스페이스, Domain 리포트 이메일 발송, LangGraph 어시스턴트.
  • 같은 방식으로 넷리스트 파싱·DB 적재 파이프라인(netlist-agent)과 LangGraph 로그 분석 플로우를 구축. 릴리스·DB 마이그레이션 절차와 러너 운영 노하우는 결정 기록으로 축적.

03

에이전트가 사내 서버를 안전하게 쓰게 하는 인프라정책 기반 MCP 서버 · LLM 게이트웨이 API 서버 · Agent Skill 허브 · 이메일 아카이빙 (2026-07 ~ 09)

문제

OpenCode·Claude Code·Codex가 공용 원격 서버의 파일과 명령, DB, 내부 API를 써야 하지만, 무엇이든 열어 주면 위험하고 폐쇄망이라 외부 서비스도 쓸 수 없습니다.

도구와 접근

디렉터리별 read/write/command 정책으로 접근을 기본 거부하고 관리자가 등록한 것만 여는 MCP 서버를 Python으로 만들고, 사내 LLM 게이트웨이 프록시·MCP REST 릴레이·투명 MCP 프로토콜 프록시를 FastAPI 서버 하나에 담았습니다. 테스트는 소켓 없는 mock으로 폐쇄망 밖에서도 돕니다.

결과물

  • MCP 서버 툴 17개(파일·명령·DB 질의·내부 API·LangGraph 파일 분석·정책 조회), 폐쇄망 pip 미러 배포 절차.
  • OpenCode 호환 Agent Skill 공유 허브(커밋 108건): Node.js 22 + SQLite, 릴리스 불변성(버전·ZIP·체크섬), 감사 로그, ZIP 경로 순회 검증, Docker + nginx.
  • 사내 이메일 아카이빙 플랫폼(변환·수집·검색, 서킷 브레이커·중단 복구 클라이언트), fail-closed SAML 랜딩 페이지.

04

개발 방법 자체를 도구로: 하네스와 오케스트레이터dev-env-blindspot · 2-하네스 스웜 · cheap-agent · custom-llm-api · 모델 A/B 벤치마크 (공개)

문제

에이전트는 자기가 모르는 것을 모른 채 코드를 쓰고, 같은 질문을 세션마다 다시 하며, 강한 모델을 모든 단계에 쓰면 토큰이 과합니다.

도구와 접근

코드를 쓰기 전에 모르는 것을 결정 가능한 질문으로 바꾸는 blindspot-pass 스킬과 읽기 전용 codebase-scanner 에이전트, 세션 시작 hook, append-only 결정 기록을 서브모듈 한 줄로 설치하는 하네스를 만들었습니다. 판단은 Opus/Fable xhigh, 병렬 실행은 Gemini Flash에 배치했습니다.

결과물

  • dev-env-blindspot(공개, 커밋 98건): 15개 이상 프로젝트 적용. 풀 버전의 토큰·시간·사용자 턴 비용을 실측한 뒤 lite로 축소, Claude Code가 계획·리뷰하고 Antigravity가 스웜 실행하는 claude-antigravity-cowork 브랜치 운영.
  • cheap-agent v0.4.1: 구독 중인 CLI의 headless 모드를 실행 엔진으로 재활용하는 자기학습 오케스트레이터(의존성 0, 파일 기반 IPC, best-of-N·세션 재개·비용 상한 등 19개 토글, GitHub Actions CI). custom-llm-api: Antigravity CLI를 API 키 없이 OpenAI 호환 API로 노출. skill-verifier: 스킬 정적 검사 + LLM 리뷰.
  • 자율 개발 스택(R14-V2): 이슈 → 스펙 → 구현 → 검증 → 리뷰 → 출하를 서브에이전트가 수행하고 사람은 PR 머지만. 같은 프롬프트 시퀀스로 Next.js 앱을 구축해 Opus와 Fable을 비교한 벤치마크 공개.
